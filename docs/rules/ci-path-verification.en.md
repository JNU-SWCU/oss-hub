# CI Verification Contract by Changed Path

[한국어](ci-path-verification.md) | **English**

English translation of the [Korean source](ci-path-verification.md).
The Korean document remains authoritative.

This document defines which verification must run for each changed path.
Path detection runs inside the required `ci` job, so `ci` always reports a result even when there are no applicable changes.
Changes to `.github/workflows/**` run every path-specific check below to prevent gaps in the verification rules themselves.

This table only maps existing verification to paths; it is not a reason to create a dedicated checker for every new contract.
The priority order in [ADR-005 (Korean)](../decisions/ADR-005-agent-driven-review-cycle.md) (structure → application tests → dedicated checkers → documentation rules) is authoritative for choosing how to enforce an invariant.
Do not add a row to this table for an invariant enforced by a higher-priority mechanism; remove the corresponding row when a checker is replaced by such a mechanism.

## Rails Execution

The rails lane runs the same `pnpm lint:structure` on PRs and main pushes and does not take the event SHA or a predecessor as input.
Pass GitHub expressions through the env boundary instead of inserting them directly into shell commands.
Do not prevent required checks from being created with workflow path filters; main pushes select every lane, including rails.
`ci-path-contract.test.mjs` always runs before dependency installation, while the generated-client drift check and Knip run in the rails lane after dependency installation.
The local root `lint` script is `pnpm -r lint && pnpm lint:structure`, and `lint:structure` uses `knip` to connect the same checks.
