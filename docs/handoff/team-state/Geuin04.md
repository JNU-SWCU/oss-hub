## 2026-09-19 — QA167 공개 랭킹 지표 확장

- 상태: PR 준비
- Issue: [#1234](https://github.com/JNU-SWCU/oss-hub/issues/1234)
- PR: 미발행
- blocker: ADR-010 `:240`의 `department` 공개 결정(2026-08-19) 철회 여부가 미확정이다. 착수 승인은 owner에게 별도 경로로 받았고 그 사실을 #1234 코멘트에 기록했다. ADR 개정은 이 판단 뒤로 미루며 이번 작업에서 문서를 건드리지 않았다.
- 내용: 공개 DTO와 랭킹 화면에 `issueCount`·`repositoryCount`·`starCount`·`total`을 더했다. `name`·`department`는 공개 계층에 넣지 않았다.
- 근거: 2026-08-24 `906c6f8e`가 공개 wire를 네 필드로 좁혔을 때 명시한 목표는 학과·실명 비노출이었다. 이 변경은 그 둘을 계속 감춘 채 지표만 되돌리므로 그 보안 목표를 깨지 않는다.
- 설계: 공개 파서는 새 지표를 관용적으로 읽어 빠진 값을 0으로 둔다. 백엔드보다 프런트가 먼저 배포되는 창에서 랭킹 화면이 통째로 죽지 않아야 하고, staff 파서가 같은 지표에 이미 같은 규칙을 쓴다.
- 설계: 공개 차단의 실제 가드는 지표가 아니라 신원이다. 고정 테스트의 제외 목록을 `department`·`displayName`·`githubId`·`id`·`name`·`userId` 여섯으로 좁히면서, 파서 테스트에 신원 세 키 부재 확인을 새로 더해 느슨해진 자리를 메웠다.
- 정정: 티켓이 지목한 고정 테스트는 두 곳이었으나 실제로는 다섯 곳이었다 — `api.test.ts` 네 건과 `ranking-view.test.tsx`의 모바일 레이아웃 테스트가 티켓에 없었다. 타입 검사가 합성 행 여덟 곳을 더 잡았고, 「활동이 0인 가입자」 합성 행 두 곳은 공용 헬퍼가 기본값을 갖게 되면서 이름과 어긋나 0으로 맞췄다.
- 정정: 티켓의 ADR-010 개정 노트 위치 `:278`은 #1277 병합(`4384b88`)으로 `:279`로 밀렸다. `:240`은 그대로다.
- 검증: backend 347 suites / 4,320 tests, frontend 366 files / 3,702 tests 통과. 타입 검사·린트·서식 양쪽 통과.
- 브라우저 검증: Chrome E2E로 Before/After 요소 캡처와 전체 화면을 각 4장 얻었다. 같은 합성 응답을 같은 조건(`/ranking?year=2026`, 비로그인, 1280x900·390x844, `dataAsOf` 고정)으로 두 코드에 먹이고 코드만 갈랐다 — Before는 main `b4ceeb83`, After는 이 브랜치다.
- 한계: 이 캡처는 UI가 응답을 어떻게 그리는지를 증명하며 실제 backend 응답을 거치지 않는다. 공개 wire의 키 구성은 `ranking.controller.spec.ts`가 고정한다.
- 공개 안전성: 합성 데이터(`synthetic-member-N`)로만 찍었고 이미지에 EXIF·텍스트 청크가 없음을 캡처 스펙이 검사한다. 운영 데이터·접속 정보·개인 경로를 이 기록에 넣지 않았다.
- 진행 경계: 병합·배포하지 않는다. ADR 개정은 owner 판단 뒤로 미룬다.
