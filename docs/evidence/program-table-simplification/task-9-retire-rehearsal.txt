# Todo 9 retirement stage: rehearsal receipts (PR #1754)
#
# Part 1 is the release receipt: a production clone, taken after #1752 and #1753
# went live as v0.24.58. Part 2 is the earlier pre-gate run on synthetic data.
#
# Part 1 data: production was only read, with pg_dump under
# default_transaction_read_only=on. Two dumps, one for the official run and one for
# the abort and Prisma probe. Both stayed on the production host in a mode-700
# directory and were deleted afterwards. Only counts, migration names, guard
# messages and schema DDL left the host.
#
# Part 1 clone: throwaway container from the production PostgreSQL image, network
# none, no published ports, 0.5 CPU, 512 MiB memory and swap, data directory on
# tmpfs. Prisma ran from the live backend image v0.24.58 with the candidate
# apps/backend/prisma mounted over /app/prisma, and could only reach the clone.
#
# Official run command:
#   bash deploy/jenkins/program-migration/team-application/server-rehearse.sh <private root> <private root>/deploy/jenkins/program-migration/team-application/retire.json
#
# Abort and Prisma probe: a throwaway script outside the repository, built on the
# official lib.sh, preflight.sh, reconcile.sh and rehearse.sh. It changes a clone
# database, then applies the unchanged migration.
#   state= is Application/ApplicationReviewHistory/Team/TeamHistory/AuditLog/
#          application_team_map/legacy GithubRepository columns/Team.answers nullable/
#          Team_application_fields_check.
#   kept= is Team/TeamMember/TeamInvitation/TeamHistory/GithubRepository/
#          RepositoryProvisionJob/RepositoryIssuanceHistory/
#          GithubRepositoryOutsiderContribution/MilestoneDocumentSubmission/
#          SubmissionFile/Notification/OutboxEvent/AuditLog/application_team_map.
#   audit_reader_rows= is the query in audit-log.repository.ts findApplicationProgramNames,
#          which still reads program_team_backup after the retirement.
#
# One probe case did not run. outsider_team_null is the MUTATION_FAILED line: the
# probe's own UPDATE selected an id column, and GithubRepositoryOutsiderContribution
# has none. The migration never ran for it, and it is the only unexpected result in
# PROBE_SUMMARY. job_team_null and submission_team_null run the same guard loop, and
# the unchanged control runs that loop for all four tables.
