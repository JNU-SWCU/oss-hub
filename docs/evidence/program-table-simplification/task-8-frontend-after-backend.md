# Todo 8 B: 지원 시 지명하고 수락 진행을 확인하는 화면

B는 수정된 A(#1724) 위의 프론트 후속 draft다. A가 운영 백엔드에 반영돼 실제 서빙 중이고 정상 상태임을 확인하기 전에는 배포하지 않는다. 릴리스 발행만으로 이 조건을 충족했다고 보지 않는다. Vercel은 Jenkins 완료를 기다리지 않는다.

## 최종 인원 규칙

지원자는 가입한 활성 학생을 검색해 지정한다. 본인과 지정한 학생 수가 최소 이상·최대 이하일 때만 제출한다. 지명 단계는 브라우저 상태만 바꾸며, 제출할 때 Team·팀장 TeamMember·지원서·초대를 같은 트랜잭션에서 만든다. 지정한 학생은 수락해야 합류한다. 최소 1명 프로그램만 혼자 제출할 수 있다. 승인은 실제 수락 인원이 최소 이상이어야 한다.

프로그램이 인원 기준을 반환하지 않으면 최소 1명으로 추정하지 않고 지원 화면을 실패 상태로 둔다. 구 프론트의 기존 준비팀 경로는 A에서 계속 지원한다. 새 신청 화면은 기존 초대 검색 패널을 재사용하지만 제출 전에는 초대 POST를 보내지 않는다. 보존된 기존 준비팀·팀이 있는 경우에는 기존 구성원을 사용한다.

## 교직원과 안내

팀 관리에서 기존 TeamMember 수와 프로그램 최소 인원으로 수락 1/2명을 표시한다. APP_019/422는 일반 재시도 메시지 대신 “팀 최소 인원이 부족해 승인할 수 없습니다. 초대한 팀원이 수락한 뒤 다시 승인해 주세요.”라고 안내한다. 거부 뒤 상태는 서버에서 재조회한 SUBMITTED로 유지한다.

해당 메시지는 기존 셀의 nowrap을 상속하지 않도록 줄바꿈과 최대 너비를 적용했다. 실제 폭이 viewport 안에 있고 scrollWidth가 clientWidth를 넘지 않는지 Chrome에서 검사한다. 학생·교직원 가이드는 지명 인원과 실제 수락 인원을 구분한다.

## 테스트와 실제 화면

인원 미달인데 제출 가능했던 보존 폼 테스트를 먼저 red로 확인했다(1 failed / 33 passed). 지원 화면·검색 패널·교직원 대상 검증은 17 files / 272 tests다. 새 인원 기준이 없는 반려 fixture 두 실패는 실제 응답에 맞게 기준을 추가해 수정했고 해당 두 테스트를 다시 통과했다. 반려 사유의 원문 표시 검증을 삭제하거나 약화하지 않았다.

Chrome은 실제 앱의 두 폭(1440×1000, 390×844)에서 최소 미달 제출 비활성 → 학생 검색·지명 → 제출 → 대기 초대 확인, 추가 초대 정원 오류, 기간 종료, 교직원의 수락 진행·승인 거부를 확인한다. 화면은 page.route 합성 API를 사용한다. 저장·인가·원자성·초대 수락 경합은 A의 실제 PostgreSQL 통합 테스트로 별도 증명한다.

실행 영수증: 학생·교직원 4개 Chrome 시나리오가 통과했다. 최종 학생 화면 2개와 가이드용 DPR 2 캡처 2개도 통과했다. frontend typecheck·lint, 구조·포맷·원장, guide build는 모두 EXIT=0이다. lint에는 기존의 테스트 목 링크 경고 4개만 남았다. 버튼까지 실제로 스크롤해 캡처했으며 기본 화면·지정 전후·접수·대기 초대·정원 오류·기간 종료·승인 거부를 확인했다. QA 서버의 LISTEN 프로세스는 0개였고 브라우저는 각 실행 종료 시 정리됐다.

Before는 배포된 기존 프론트, After는 B 후보의 실제 실행 화면이다. origin이 다르며 합성 사용자·프로그램·고정 시각을 동일하게 둔다. 지원 폼·성공은 main[data-slot=page-body], 승인 거부는 해당 행의 role=status를 캡처한다. 개발 도구 표시만 숨겼으며 실제 내용을 합성 이미지로 재작성하지 않았다.

## 코드 검토와 남은 경계

새 지명 UI는 기존 검색 API·검색 패널·디바운스 hook을 재사용한다. 로컬 지명 목록을 실제 초대나 TeamMember로 가장하지 않는다. 명시적인 inviteeUserIds만 최종 지원에 보내며 서버가 중복·본인·정원·자격·소속을 다시 검증한다. 새 framework·전역 상태·데이터 저장소·capability fallback은 없다.

기존 큰 page는 요청 세대·입력 보존·기존 준비팀 호환을 유지하고, 새 검색·지명 UI만 별도 컴포넌트로 분리했다(SIZE_OK). 기존 page를 전면 분해하면 이번 배포 경계를 넘어선다. 독립 gate 승인은 이 자체 검토와 별개다.

계약 26-1의 REJECTED 취소와 기존 팀 탈퇴 안내 공백은 원장의 Todo 9에 남겼다. TeamHistory 이관·옛 구조 사용 중단·물리 DROP은 이번에 시작하지 않았다. 운영 데이터 이관·삭제는 각각 0건이고 schema migration이 없어 서버 이관 리허설은 해당하지 않는다.
