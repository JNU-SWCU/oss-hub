Todo 2 후속 릴리스: 물리 컬럼 삭제와 API 상태값 전환 (2026-11-03)

반드시 먼저 배포할 릴리스:
PR #1718
92f2bff157d5691ea53ff891fa1e6a54a56c0065
해당 frontend와 backend가 모두 실행된 뒤에만 후속 마이그레이션을 적용한다.
두 PR을 같은 배포에 포함하지 않는다.

배포 담당자는 운영 덤프 복원 검증, 사전 점검과 백업을 별도로 완료해야 한다.
여기서는 운영 접속·덤프 취득·운영 백업·머지·배포를 수행하지 않았다.
SQL이 실제 실행 중인 앱 버전을 판별하지는 않는다. 릴리스 경계는 배포 절차의 필수 조건이다.

물리 변경
- TeamMember: 기존 (teamId, userId) UNIQUE 인덱스를 PK로 승격한다.
- TeamMember: id, name, email, department를 삭제한다.
- Team: joinCodeDigest를 삭제한다.
- TeamInvitation: invitedAt을 삭제한다. 공개 응답 키는 createdAt에서 계속 제공한다.
- programId 복합 FK와 프로그램당 한 팀 유니크는 유지한다.
- 새 incoming FK가 있으면 삭제 전에 트랜잭션을 중단한다.

상태값
ApplicationsService와 ProgramTeamsService가 원래 RepositoryProvisionJobStatus를 반환한다.
FAILED_RETRYABLE / FAILED_FINAL 대신 별도 이름을 만들던 두 매퍼를 삭제했다.
프론트 표준 타입도 원래 이름이다. 교체 중인 직전 backend의 값은 DTO 입력 경계에서만 함께 받는다.
아카이브는 SubmissionStatus.SUBMITTED를 사용하고 CSV 표시 문구는 그대로다.
팀 화면의 소문자 stage 별칭은 선행 릴리스에서 이미 제거했다.
다른 기능의 PENDING, EXPIRED 및 프로비저닝 작업 상태 머신은 변경하지 않았다.

실패 탐침
stale_state: 기존 테스트 DB를 재사용하지 않고 매 실행마다 새 project/빈 DB에서 migrate deploy했다.
dirty_worktree: 첫 커밋 전 git diff --quiet의 EXIT=1을 확인했다. 소유하지 않은 변경은 없었다.
misleading_success_output: 성공 문구를 출력하는 runner 대역의 EXIT=17을 그대로 전달했다.
cleanup_failure: 테스트 성공이어도 정리 실패 EXIT=23을 그대로 전달했다.
flaky_tests: 신규 테스트는 sleep 없이 고정 시각·완료된 DB 작업·브라우저 상태 assertion을 사용한다.
초대·탈퇴는 독립된 빈 DB 실행에서 반복 통과했고 브라우저 retries는 0이다.
