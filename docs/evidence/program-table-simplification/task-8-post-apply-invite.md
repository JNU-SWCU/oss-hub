# Todo 8 첫 릴리스: 지원 후 초대

## 릴리스 경계

소유자가 승인한 순서는 세 릴리스다. 임시 DB 트리거는 추가하지 않는다.

1. 지원 후 초대와 최소 인원 검사의 승인 시점 이동. 두 앱과 가이드를 함께 배포한다.
2. 계약 6의 범용 `TeamHistory` 도입, 종료 초대 이관, 대기 초대만 유지하는 쓰기로 전환, Preparation과 초대 status 사용 중단. Todo 9가 같은 이력을 재사용한다.
3. 직전 앱이 옛 구조를 사용하지 않는 것을 확인한 다음 물리 DROP. 별도의 stacked draft PR로 제공하고 실제 전환 승인을 받는다.

이 PR은 첫 릴리스다. 마이그레이션과 Prisma schema 변경이 없으며 직전 릴리스와 같은 스키마에서 실행된다. Preparation API와 테이블, 초대 status 및 respondedAt의 물리 제거는 완료하지 않았다. 데이터 이관 리허설은 데이터 마이그레이션을 포함하는 후속 PR에서 수행한다.

## 변경한 동작

- 학생은 팀 이름과 동의를 입력해 혼자 지원한다. 지원 트랜잭션이 팀과 신청서를 함께 만든다.
- 새 지원 화면에서는 준비팀을 만들거나 초대를 보내지 않는다. 성공 화면의 `우리 팀 보기`에서 기존 팀 초대 기능으로 이어진다.
- 승인 트랜잭션은 기존 팀 잠금을 획득한 뒤 실제 팀원 수와 프로그램 최소 인원을 조회한다. 미달이면 `APP_019`로 거부하고 상태·이력·알림·outbox를 변경하지 않는다.
- 초대를 수락한 뒤 최소 인원을 채우면 같은 지원을 승인할 수 있다.
- 이전 화면에서 만든 준비팀의 조회·해제 경로는 다음 사용 중단 릴리스까지 유지한다. 준비팀 차단만 단독 배포하지 않는다.

## TDD와 회귀

기존 “최소 인원 미달이면 지원 거부”와 “지원 전 준비팀 생성” 기대는 새 계약과 충돌했다. 이를 승인 시점 검증과 지원 제출의 중복 방지·입력 보존·늦은 응답 경합 회귀로 전환했다. 실패를 숨기기 위한 skip이나 assertion 완화는 넣지 않았다.

- 변경 전 backend 통합 회귀: 1 failed / 25 passed, `EXIT=1`. 최소 2명 프로그램의 혼자 지원이 기존 최소 인원 검사에서 거부됐다.

## 검증 범위

`stale_state`는 통합 실행기의 빈 DB부터 전체 migrate deploy로 검증했다. 운영 DB 쓰기·배포·머지·Jenkins 실행은 하지 않았다. 성능 개선을 측정하거나 주장하지 않는다.

- `dirty_worktree`: 시작 시 지정 브랜치와 clean 상태를 확인했다. 이번 변경만 커밋 대상으로 삼는다.
- `misleading_success_output`: 모든 테스트의 실제 suite/test 수와 EXIT를 함께 확인했다. 의도된 red와 fixture 실패는 성공으로 집계하지 않았다.
- `flaky_tests`: backend 대상 테스트가 대상 실행과 전체 실행에서 모두 통과했다. 브라우저 retries는 0이며 고정 시계를 사용한다. 새 테스트에 sleep을 넣지 않았다.
- 데이터 마이그레이션·롤백·운영 리허설: 첫 릴리스에 해당 없음. 후속 두 단계는 별도 검증이 필요하다.
- 새 로그인·secret·외부 쓰기·성능 주장: 해당 없음.

## 화면과 정리

변경 전은 배포된 v0.24.32, 변경 후는 이 브랜치의 프론트 실행 화면이다. 두 환경 모두 같은 합성 사용자·프로그램과 고정 시각을 사용했다. origin은 다르다. 요소 캡처는 두 화면 모두 `main[data-slot="page-body"]`이며 지원 폼과 성공 상태를 비교했다. 초기 화면·제출 버튼까지 스크롤한 화면·성공·초대 후·정원 오류·기간 외 상태를 캡처했다. 새 색이나 공용 컴포넌트 규격은 추가하지 않았다.

모바일에서 버튼과 오류 문구가 잘리거나 겹치지 않는 것을 직접 확인했다. 기존 내부 스크롤을 유지하며 제출 버튼까지 스크롤해 조작했다. 지원 전 초대 버튼을 없애고 성공 후 `우리 팀 보기`로 다음 작업을 연결한다. 어두운 테마와 전체 WCAG 자동 평가는 이번 실행에서 별도로 측정하지 않았다.

통합 실행기는 종료 시 임시 Docker 프로젝트와 볼륨을 제거했다. Playwright의 브라우저와 QA 서버는 실행 종료 시 정리됐고, 사용한 QA 포트의 LISTEN 프로세스는 0개였다. 운영 집계용 임시 SQL은 제거했다. worktree와 로컬 증거 캡처는 PR 검토를 위해 보존한다.
