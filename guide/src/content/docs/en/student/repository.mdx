Team repositories come from two sources. If a program provisions repositories, one is created automatically on approval. Teams using their own public repository register its URL in `우리 팀` (Our team).

## Check a provisioned repository

<Steps>
1. Open `내 저장소` (My repositories) in the left menu.
2. Check the repository card's status. If it says `저장소 생성 중` (Creating repository), wait a moment.
3. If it says `초대 수락 대기` (Awaiting invitation acceptance), accept the repository invitation on GitHub yourself. OSS Hub does not accept it for you.
4. Click `GitHub에서 열기` (Open on GitHub) to open the repository.
</Steps>

Repository creation and invitation delivery are automatic. Accepting the invitation is the only step you do yourself. In `우리 팀` (Our team), `프로젝트 저장소` (Project repository) also shows the stages `신청 승인` (Application approved), `저장소 생성` (Repository creation), and `사용 가능` (Ready to use). Even when all stages are complete, you must accept your GitHub invitation yourself. If `운영진에게 문의하세요.` (Contact the organizers) appears, contact the program staff.

## Register your own repository

Only the team leader can register a repository, and only after application approval and before the program ends. The repository must be public on GitHub.

Replacing the address removes the previous repository's OSS Hub registration and collected records. The original repository stays on GitHub.

<Steps>
1. Open `우리 팀` (Our team) from the dashboard card and find `프로젝트 저장소` (Project repository).
2. Click ② `변경` (Change) to edit the address inside the card.
3. Enter the GitHub repository address in ③ `저장소 주소` (Repository address).
4. Click ④ `저장` (Save). To leave without saving, click `취소` (Cancel). If you edited the address, click `변경사항 버리기` (Discard changes) in the confirmation dialog.
</Steps>

## Check repository details and change history

Members of approved teams can click the repository name in `프로젝트 저장소` to open it on GitHub. When available, `기본 브랜치` (Default branch) and `마지막 수집` (Last collected) appear below the name. If no repository is linked, the card says `연결된 저장소가 없습니다.` (No repository connected).

The `변경 이력` (Change history) button may show the number of records you can view. The list loads the first time you expand it. Each entry shows the date, who made the change, and the old and new repositories. Click `변경 이력 더 보기` (Show more changes) when available. Team members can view this history even if they are not the team leader.

<Success>
`저장소 변경을 저장했습니다.` (Repository changes saved) appears, and activity collection starts automatically. View the collected activity in [Activity](/oss-hub/en/student/activity/).
</Success>

<Recover title="When you cannot register a repository">
- The editing card does not appear before approval. If you are not the team leader or the program has ended, `변경` is disabled and the card says `승인된 팀의 팀장만 프로그램 종료 전까지 변경할 수 있습니다.` (Only the leader of an approved team can make changes before the program ends).
- If OSS Hub cannot confirm the save, click `다시 불러오기` (Reload) and check the current address before saving again.
- `연결하려는 저장소를 찾을 수 없거나 비공개 저장소입니다. GitHub에 공개된 저장소만 연결할 수 있습니다.` (The repository was not found or is private. Only public GitHub repositories can be linked): check for a mistyped URL and confirm that the repository is public.
- `다른 신청에 연결된 저장소입니다.` (This repository is linked to another application): another team is using it.
- `저장소를 처리 중입니다…` (Processing the repository…): check again shortly.
- `GitHub 저장소를 확인할 수 없습니다…` (Cannot check the GitHub repository…): GitHub may be having a problem. Wait and try again.
- Linking an external repository also requires up-to-date consent. Check [signup consent](/oss-hub/en/student/sign-up/).
- The screen does not explain the ownership verification rules for registering someone else's repository. <Verified status="policy" />
</Recover>
