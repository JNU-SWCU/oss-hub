`시스템 상태` (System status) shows whether repository provisioning, GitHub activity collection, and notification mail are running correctly. Open it first when someone reports that student activity counts have stopped changing or a team repository was never created. Only administrators can open this screen.

Collection runs automatically at the top of every hour, and every Sunday at 03:00 it rereads everything.

## Read the screen

<Steps>
1. Open `시스템 상태` (System status) in the `관리자` (Administrator) group on the left.
2. Check the card at the top. If it says `이상 없음` (No issues), there's nothing to do.
3. If you see `주의 필요` (Needs attention), handle each item as described below.
4. Check the numbers for each area in `구역 현황` (Area status) below.
</Steps>

## Needs attention

This card appears only when something needs work. Each item has a `심각` (Severe) or `주의` (Warning) badge and a count, and severe items come first.

<Shot src="admin/status-attention.webp" alt="The needs attention card. Under final repository provisioning failure, each team has a Retry button. Under delayed activity collection, five delayed repositories and a show more button are listed. Notification mail failure is at the bottom." caption="Needs attention" />

- `저장소 발급 최종 실패` (Repository provisioning failed): Teams whose repository could not be created. Each row shows the team, program, error code, and last attempt time. Click `다시 시도` (Retry) to request provisioning again.
- `활동 수집 지연` (Activity collection delayed): Repositories whose last successful collection is more than 2 hours old. The five most delayed repositories are shown, and `지연 저장소 N개 더 보기` (Show N more delayed repositories) expands the rest. If they're still delayed after the next hourly collection, go to Settings, then GitHub Apps, in the program office's GitHub organization and check that the collection app is installed and has permission.
- `알림 메일 발송 실패` (Notification mail failed): The number of notification emails that couldn't be sent in the last 7 days.
- Items that point to a person, such as administrator permission changes or bulk rejections and deletions, have a `사용자 보기` (View user) link that opens that user's page.

A repository that fails is tried again in the next hourly collection. When that collection succeeds, it leaves `활동 수집 지연` (Activity collection delayed).

The screen doesn't describe how to escalate a lasting stall to the service operator or developer. <Verified status="policy" />

## Area status

Each area has one row with a status badge and its numbers.

| Area | Badge | Numbers |
| --- | --- | --- |
| `저장소 발급` (Repository provisioning) | `정상` (Normal), or `실패` (Failed) when a final failure exists | `대기 중` (Waiting), `생성 중` (Creating), `재시도 대기` (Waiting to retry), `생성 실패` (Failed) |
| `활동 수집` (Activity collection) | `정상` (Normal), `지연` (Delayed), or `추적 대상 없음` (No tracked targets). `수집 중` (Collecting) is added while collection runs. | `추적 저장소` (Tracked repositories), `지연 저장소` (Delayed repositories), `마지막 수집 성공` (Last successful collection), `다음 주기 예상` (Expected next cycle), `외부 추적 저장소` (External tracked repositories), `외부 마지막 수집 성공` (External last successful collection) |
| `알림 메일` (Notification mail) | `정상` (Normal), or `실패` (Failed) when a send failed in the last 7 days | `최근 7일 발송` (Sent in last 7 days), `실패` (Failed), `마지막 발송` (Last sent) |

`추적 대상 없음` (No tracked targets) means there are no team repositories to collect yet. A repository isn't registered or collected just because it belongs to the organization. The `외부` (External) numbers cover student personal repositories, which are collected with the organization at the top of every hour. When there's no record, `기록 없음` (No record) appears.

## Run collection now

When it can't wait for the next hour, start collection right away. Click `지금 수집 실행` (Run collection now) at the top right. Collection takes time, so one click is enough.

While `활동 수집` (Activity collection) shows the `수집 중` (Collecting) badge, the button is gray. Try again after it finishes. While the request is being sent, `실행 요청 중…` (Requesting…) appears briefly.

<Success>
You see `수집 요청을 접수했습니다.` (Collection request accepted) appears. Collection runs in the background, so `마지막 수집 성공` (Last successful collection) may not change right away. Give it some time, then refresh.
</Success>

<Recover title="If collection doesn't start or the screen won't open">
- `수집을 시작하지 못했습니다. 잠시 후 다시 시도해 주세요.` (Collection couldn't be started. Try again shortly.): Wait and click again.
- `저장소 발급을 다시 시도하지 못했습니다` (Provisioning couldn't be retried): Wait and click `다시 시도` (Retry) again.
- `저장소 발급은 이미 다시 시도했거나 끝났습니다` (Provisioning was already retried or finished): The request was already handled. You don't need to click again.
- `시스템 상태를 불러오지 못했습니다` (System status couldn't be loaded): Refresh the page.
- `최신 상태를 불러오지 못했습니다` (The latest status couldn't be loaded): Click `상태 다시 불러오기` (Reload status).
</Recover>
