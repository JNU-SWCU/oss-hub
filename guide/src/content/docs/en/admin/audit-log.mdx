`감사 로그` (Audit log) shows who changed what and when. It covers access changes, program operations, document decisions, and sign-ins. Only Administrators can open it. Records cannot be edited or deleted here.

## Choose a category and view

<Steps>
1. Open ① `감사 로그` (Audit log) in the left-hand `관리자` (Administrator) section.
2. In ② the category row, choose `전체` (All), `권한·계정` (Access and accounts), `운영` (Operations), `서류` (Documents), `로그인` (Sign-ins), or `시스템` (System). The category applies immediately.
3. On wide screens, use ③ the view selector to switch between `피드` (Feed) and `표` (Table). Feed is the default and the only view on narrow screens.
</Steps>

<Shot src="admin/audit-full.webp" alt="Audit log feed with a collapsed group of sign-in records. ① marks the sidebar menu, ② the categories, and ③ the view selector." caption="① Audit log menu ② Categories ③ View selector" />

Category counts reflect the search term, action type, and dates. Switching categories does not change the counts displayed beside the other categories.

## Narrow the search and dates

<Steps>
1. Under `기간` (Period), choose `최근 7일` (Last 7 days), `최근 30일` (Last 30 days), or `직접 지정` (Custom). For a custom range, enter `시작일` (Start date) or `종료일` (End date) as needed.
2. Choose a `작업 종류` (Action type). On wide screens, changes to the period, dates, and action type apply immediately.
3. Enter a name or GitHub ID in `검색` (Search), then press Enter. On narrow screens, open `필터` (Filters) first, set the conditions, then choose `적용` (Apply).
</Steps>

## Read the feed and table

`피드` (Feed) groups records by date, newest first. When both the category and action type are `전체` (All), the feed can fold consecutive sign-ins, failed sign-ins, and sign-outs from the same day into one row. The row shows the total and the number of failures. Select it to see the individual records. To see only session records without grouping, choose `로그인` (Sign-ins) in the category row.

<Steps>
1. On a wide screen, choose ① `표` (Table).
2. In ② the table, read individual records in `시각` (Time), `행위자` (Actor), `작업` (Action), `대상` (Target), and `결과` (Result). Select a record in either view to open `기록 상세` (Record details). If the record includes a change, compare the old and new values there.
</Steps>

<Shot src="admin/audit-content-closeup.webp" alt="① marks the Table view button. ② marks the table with three individual sign-in records." caption="① Table view ② Individual sign-in records" />

When results span multiple pages, use `이전` (Previous) and `다음` (Next) below. Existing bookmarks and search links retain the scope specified in the link. A link that sets only a category or action, with no period, shows the full history instead of the last 30 days. If a link asks for a page past the end of the results, the last page opens.

Records with the same time and content are all listed, never merged into one. The count on a folded sign-in row matches the actual number of records.

Distinguish these action types:

- To find mail records, choose an option in `작업 종류` (Action type), such as `프로그램 메일 발송 시도` (Program mail send attempt) or `마감 알림 발송 결과` (Deadline reminder send result). If a program mail batch has any confirmed failure, its result appears as `프로그램 메일 일부 실패` (Program mail partially failed) or `프로그램 메일 발송 실패` (Program mail failed).
- Staff access decisions use `권한 요청 승인` (Access request approved), `권한 요청 반려` (Access request rejected), `권한 회수` (Access revoked), and `권한 복구` (Access restored). There are also `교직원 승인` (Staff approved) and `교직원 승인 회수` (Staff approval revoked) records.
- Program applications use `신청 제출` (Application submitted), `신청 재제출` (Application resubmitted), `신청 승인` (Application approved), `신청 반려` (Application rejected), and `검토 대기로` (Returned to pending review). These differ from staff access requests.
- Documents use `서류 제출` (Document submitted), `서류 재제출` (Document resubmitted), `서류 수정 요청` (Document changes requested), `서류 승인` (Document approved), and `서류 반려` (Document rejected).
- Find membership type records under `회원 유형 변경` (Membership type changed). An initial selection appears as `회원 유형 선택` (Membership type selected) in the record.
- Account sessions use `로그인` (Sign-in), `로그인 실패` (Sign-in failed), and `로그아웃` (Sign-out). An unlisted action may display its original code.

<Success>
The results match the applied conditions. Switching between Feed and Table preserves the conditions and page.
</Success>

<Recover title="If records are missing or cannot be loaded">
If you see `기록이 없습니다` (No records) and `조회 조건을 바꿔 보세요.` (Try changing the search conditions), check the search spelling and category. Clear the search term or choose a wider period and try again.

If you see `감사 로그를 불러오지 못했습니다. 잠시 후 다시 시도하세요.` (The audit log could not be loaded. Try again shortly), click `다시 시도` (Retry). If it keeps happening, check [System status](/oss-hub/en/admin/system-status/).
</Recover>
