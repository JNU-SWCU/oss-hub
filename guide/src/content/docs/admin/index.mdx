`관리자`는 OSS Hub 계정의 권한과 상태를 관리하고, 서비스가 정상으로 돌아가는지 살피며, 교직원 권한 요청도 처리하는 역할입니다. 프로그램 운영 화면은 승인된 `교직원`만 열 수 있으며, 관리자 접근만으로는 열리지 않습니다.

## 관리자가 하는 일

| 하는 일 | 왜 하나요 |
| --- | --- |
| 교직원 권한 요청 승인과 반려 | 교직원 화면은 승인된 계정만 쓸 수 있습니다. |
| 가입 유형 되돌리기, 관리자 접근, 계정 상태 변경 | 잘못 가입했거나 계정을 비활성화해야 할 때 맞춥니다. |
| 감사 로그 확인 | 누가 언제 무엇을 바꿨는지 되짚습니다. |
| 시스템 상태 확인 | GitHub 활동 수집이 멈췄는지 살핍니다. |

## 5분 안에 시작하기

<Steps>
1. GitHub 계정으로 로그인합니다. 관리자 접근이 있는 계정이면 위쪽에 `관리자` 표시가 보입니다.
2. 위쪽 `대시보드`를 누릅니다. 관리자 전용 계정은 `사용자 목록`이 열립니다. 자세한 차이는 [처음 들어가기](/oss-hub/admin/first-entry/)에 있습니다.
3. 왼쪽 `관리자` 묶음에서 `가입 신청`을 열어 승인을 기다리는 요청이 있는지 봅니다.
4. `사용자 목록`에서 계정의 회원 유형, 관리자 접근, 계정 상태를 확인합니다.
5. `시스템 상태`에서 수집 상태가 `정상`인지 봅니다. `정상`이 아니면 [시스템 상태 확인하기](/oss-hub/admin/system-status/)를 따라 원인을 찾습니다.
</Steps>

첫 관리자 계정은 화면에서 만들 수 없습니다. 서버를 설치한 운영 담당자가 서버 설정에 첫 관리자 계정을 적어 두면, 그 계정이 처음 로그인할 때 관리자 역할을 받습니다. 이미 권한이 있는 계정에는 적용되지 않습니다. 첫 관리자가 없다면 운영 담당자에게 지정을 요청하세요. 이후에는 이 가이드의 [회원 유형과 관리자 접근 바꾸기](/oss-hub/admin/change-role/)로 다른 관리자를 지정합니다.

## 업무별 안내

- [처음 들어가기](/oss-hub/admin/first-entry/): 로그인 후 어디에서 시작하는지, 프로그램 운영은 어디로 들어가는지 설명합니다.
- [교직원 권한 요청 처리하기](/oss-hub/admin/applicants/): `가입 신청`에서 승인하거나 반려합니다.
- [사용자 찾아보기](/oss-hub/admin/find-users/): 검색과 필터, 표 읽는 법입니다.
- [가입 유형 되돌리기와 관리자 접근 바꾸기](/oss-hub/admin/change-role/): 가입 유형을 되돌리고 관리자 접근을 바꾸는 방법과 변경이 막혔을 때 해결하는 방법입니다.
- [계정 비활성화와 재활성화](/oss-hub/admin/deactivate/): 계정을 비활성화하고 되살립니다.
- [감사 로그 보기](/oss-hub/admin/audit-log/): 관리 작업 이력을 찾습니다.
- [시스템 상태 확인하기](/oss-hub/admin/system-status/): 수집 상태를 읽고 `지금 수집 실행`을 쓰는 법입니다.
- [학생 활성 보기](/oss-hub/admin/insights/): 승인된 교직원이 전공별 활동과 참여 현황을 봅니다.
- [프로그램 삭제하기](/oss-hub/admin/delete-program/): 프로그램을 목록에서 숨기고 파일을 정리하는 방법을 다룹니다.
- [내 설정과 알림](/oss-hub/admin/my-settings/): 알림 수신을 정하고 본인 계정을 비활성화하는 법입니다.

## 헷갈리기 쉬운 점

`가입 신청`은 `교직원` 역할을 달라는 요청을 처리하는 곳입니다. 프로그램에 신청한 학생을 심사하는 일과 다릅니다. 프로그램 신청자 심사는 프로그램 안의 `팀 관리`에서 합니다.

교직원 권한은 프로그램별로 나뉘지 않습니다. 승인된 교직원은 모든 프로그램의 운영 화면을 열 수 있습니다. 관리자 접근만 있는 계정은 열 수 없습니다. <Verified status="policy" />
