잘못 만든 프로그램을 정리해야 할 때 씁니다. 삭제는 관리자만이 아니라 교직원도 할 수 있습니다.

<Shot src="admin/program-danger-zone.webp" alt="프로그램 편집 화면 맨 아래의 위험 영역. ①이 프로그램 삭제 버튼을 가리킵니다." caption="① 프로그램 삭제" />

## 삭제 전에 알아 둘 것

삭제하면 되돌릴 수 없습니다. 휴지통도, 복구 화면도 없습니다. 지워지는 것은 지원서, 팀, 게시글, 제출물, 제출·검토·파일 이력입니다. 지워도 되는지 확실하지 않으면 지우지 마세요.

삭제를 막는 조건은 없습니다. 지원자나 제출물이 있어도, 진행 중인 프로그램이어도 눌리는 대로 지워집니다. 시스템이 대신 막아 주지 않으므로, 지우는 사람이 직접 확인해야 합니다.

남는 것은 감사 기록과 사용자 계정입니다. [감사 로그](/oss-hub/admin/audit-log/)에는 `프로그램 삭제` 기록만 남고, 어느 프로그램이었는지도 거기서 찾을 수 있습니다.

프로그램에 연결된 GitHub 저장소는 지워지지 않습니다. 이 서비스와의 연결만 끊어지므로 GitHub에는 그대로 남습니다. 업로드한 제출 파일은 삭제 직후가 아니라 이후 정리 작업으로 지워집니다.

프로그램을 지우지 않고 치워 두는 보관 기능은 화면에 없습니다. 감사 로그의 작업 종류에 `보관`과 `복구`가 보이지만, 지금은 그 작업을 일으키는 화면이 없습니다. 끝난 프로그램은 지우지 말고 그대로 두세요.

## 삭제하기

<Steps>
1. 위쪽 `프로그램`에서 지울 프로그램을 열고 오른쪽 위 `편집`을 누릅니다. 끝난 프로그램은 `전체`에 보이지 않으니 왼쪽 `종료` 탭에서 찾으세요.
2. 맨 아래 `위험 영역`에서 ① `프로그램 삭제`를 누릅니다.
3. `삭제 범위 확인 중…`이 끝나면 ① `삭제될 데이터` 상자에서 지원서, 팀, 게시글, 제출물, 이력 건수를 읽습니다.
</Steps>

이 건수가 예상과 다르면 여기서 `취소`를 누르세요. 다음 단계부터는 되돌릴 수 없습니다.

<Steps>
4. `프로그램을 삭제할까요?` 창에서 ② `삭제`를 누릅니다. `삭제 중…`이 끝날 때까지 기다립니다.
</Steps>
<Shot src="admin/program-delete-dialog.webp" alt="프로그램을 삭제할까요 확인 창. ①이 삭제될 데이터 건수 상자, ②가 삭제 버튼을 가리킵니다." caption="① 삭제될 데이터 ② 삭제" />

<Success>
프로그램 목록으로 이동하고, 목록 위에 `프로그램 전체 삭제를 완료했습니다` 안내가 나옵니다. 그 아래에 `지원서 N건 · 팀 N건 · 게시글 N건 …`처럼 지운 데이터 건수가 항목별로 나옵니다. 지울 데이터가 없었다면 `연결된 데이터가 없었습니다.`가 나옵니다. 잠깐 뜨는 알림이 아니라 목록 위에 머무는 안내입니다.
</Success>

<Recover title="삭제가 끝나지 않을 때">
- `삭제 범위를 확인하지 못했습니다. 다시 시도해 주세요.`: 창을 닫고 `프로그램 삭제`를 다시 누르세요.
- `삭제 범위가 변경되었습니다. 내용을 확인한 뒤 삭제를 다시 눌러 주세요.`: 그사이 데이터가 늘거나 줄었습니다. 바뀐 건수를 읽고 다시 판단하세요.
- `전체 삭제 실패` 제목 아래 실패 안내(서버가 사유를 주면 그 문장, 아니면 `프로그램 전체를 삭제하지 못했습니다. 잠시 후 다시 시도해 주세요.`): 삭제는 한 번에 처리되므로 실패하면 아무것도 지워지지 않습니다. 프로그램 목록에 프로그램이 그대로 있는지 확인하고 다시 시도하세요.
</Recover>
