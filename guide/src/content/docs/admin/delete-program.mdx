잘못 만든 프로그램을 정리해야 할 때 씁니다. 승인된 교직원만 삭제할 수 있으며, 관리자 접근만 있는 계정은 삭제할 수 없습니다.

<Shot src="admin/program-status-delete-danger.webp" alt="프로그램 편집 화면의 위험 영역. 프로그램을 목록에서 숨기고 업로드한 파일을 삭제한다는 설명과 프로그램 삭제 버튼이 있습니다." caption="프로그램 삭제" />

## 삭제 전에 알아 둘 것

삭제하면 프로그램의 상태만 삭제로 바뀌고 공개 목록과 교직원 목록에서 사라집니다. 프로그램, 지원서, 팀, 게시글, 제출물과 이력은 기록으로 보존됩니다. 복구 화면은 없습니다.

지원자나 제출물이 있어도, 진행 중인 프로그램이어도 삭제 상태로 바꿀 수 있습니다. 연결된 기록의 개수를 확인한 뒤 진행하세요.

사용자 계정과 감사 기록도 유지됩니다. [감사 로그](/oss-hub/admin/audit-log/)에는 `프로그램 삭제` 기록이 남으니, 어느 프로그램이었는지는 거기서 찾을 수 있습니다.

프로그램에 연결된 GitHub 저장소와 서비스 안의 연결 기록은 지워지지 않습니다. 파일 정리 대상으로 예약된 제출 파일, 양식과 자체 커버의 실제 파일은 이후 정리 작업에서 삭제됩니다. 파일 메타데이터가 남더라도 삭제된 파일의 내용은 다시 내려받을 수 없습니다.

프로그램을 지우지 않고 치워 두는 보관 기능은 화면에 없습니다. 감사 로그의 작업 종류에 `보관`과 `복구`가 보이지만, 지금은 그 작업을 실행하는 화면이 없습니다. 끝난 프로그램은 지우지 말고 그대로 두세요.

## 삭제하기

<Steps>
1. 위쪽 `프로그램`에서 지울 프로그램을 열고 오른쪽 위 `편집`을 누릅니다. 끝난 프로그램은 `전체`에 보이지 않으니 왼쪽 `종료` 탭에서 찾으세요.
2. 맨 아래 `위험 영역`에서 `프로그램 삭제`를 누릅니다.
3. `삭제 범위 확인 중…`이 끝나면 `연결된 기록` 상자에서 지원서, 팀, 게시글, 제출물, 이력의 개수를 읽습니다.
</Steps>

이 개수가 예상과 다르면 여기서 `취소`를 누르세요. `삭제`를 누르면 되돌릴 수 없습니다.

<Steps>
4. `프로그램을 삭제할까요?` 창에서 `삭제`를 누릅니다. `삭제 중…`이 끝날 때까지 기다립니다.
</Steps>
<Shot src="admin/program-status-delete-dialog.webp" alt="프로그램을 목록에서 숨기고 파일을 정리한다는 삭제 확인 창. 연결된 기록의 개수와 취소·삭제 버튼이 표시됩니다." caption="연결된 기록을 확인한 뒤 삭제" />

<Success>
프로그램 목록으로 이동하고, 목록 위에 `프로그램을 목록에서 숨겼습니다` 안내가 나옵니다. 그 아래에는 정리를 예약한 업로드 파일 건수가 표시됩니다. 파일 정리 대상이 없으면 `정리할 업로드 파일이 없습니다.`가 나옵니다. 기록이 없다는 뜻은 아닙니다.
</Success>

<Recover title="삭제가 끝나지 않을 때">
- `삭제 범위를 확인하지 못했습니다. 다시 시도해 주세요.` 창을 닫고 `프로그램 삭제`를 다시 누르세요.
- `삭제 범위가 변경되었습니다. 내용을 확인한 뒤 삭제를 다시 눌러 주세요.` 그사이 데이터가 늘거나 줄었습니다. 바뀐 건수를 읽고 다시 판단하세요.
- `프로그램 삭제 실패`: 제목 아래에 사유가 나옵니다. 서버 장애면 `요청을 처리하지 못했습니다. 잠시 후 다시 시도해 주세요.`, 연결이 끊기면 `프로그램 전체를 삭제하지 못했습니다. 잠시 후 다시 시도해 주세요.`입니다. 상태 전환과 파일 정리 예약은 한 트랜잭션으로 처리됩니다. 목록에 프로그램이 그대로 있는지 확인하고 다시 시도하세요.
</Recover>
