잘못 만든 프로그램을 정리해야 할 때 씁니다. 승인된 교직원만 삭제할 수 있으며, 관리자 접근만 있는 계정은 삭제할 수 없습니다.

<Shot src="admin/program-danger-zone.webp" alt="프로그램 편집 화면 맨 아래의 위험 영역. ①이 프로그램 삭제 버튼을 가리킵니다." caption="① 프로그램 삭제" />

## 삭제 전에 알아 둘 것

삭제 요청이 처리되면 프로그램은 목록에서 제외됩니다. 이 작업은 되돌릴 수 없고, 휴지통이나 복구 화면도 없습니다. 삭제 전에 프로그램 이름과 연결된 항목을 확인하세요.

지원자나 제출물이 있거나 진행 중인 프로그램도 삭제를 요청할 수 있습니다. 삭제해도 되는지 확실하지 않으면 취소하고, 해당 프로그램을 운영하는 교직원과 먼저 확인하세요.

감사 기록과 사용자 계정은 유지됩니다. [감사 로그](/oss-hub/admin/audit-log/)에는 `프로그램 삭제` 기록이 남으니, 어느 프로그램이었는지는 거기서 찾을 수 있습니다.

이 작업으로 GitHub의 저장소 자체를 삭제하지는 않습니다. 업로드한 제출 파일은 삭제 요청 처리 후 정리 작업에서 지워집니다.

프로그램을 지우지 않고 치워 두는 보관 기능은 화면에 없습니다. 감사 로그의 작업 종류에 `보관`과 `복구`가 보이지만, 지금은 그 작업을 실행하는 화면이 없습니다. 끝난 프로그램은 지우지 말고 그대로 두세요.

## 삭제하기

<Steps>
1. 위쪽 `프로그램`에서 지울 프로그램을 열고 오른쪽 위 `편집`을 누릅니다. 끝난 프로그램은 `전체`에 보이지 않으니 왼쪽 `종료` 탭에서 찾으세요.
2. 맨 아래 `위험 영역`에서 ① `프로그램 삭제`를 누릅니다.
3. `삭제 범위 확인 중…`이 끝나면 ① `연결된 항목` 상자에서 지원서, 팀, 게시글, 제출물, 이력의 개수를 읽습니다.
</Steps>

이 개수가 예상과 다르면 여기서 `취소`를 누르세요. `삭제`를 누르면 되돌릴 수 없습니다.

<Steps>
4. `프로그램을 삭제할까요?` 창에서 ② `삭제`를 누릅니다. `삭제 중…`이 끝날 때까지 기다립니다.
</Steps>
<Shot src="admin/program-delete-dialog.webp" alt="프로그램을 삭제할까요 확인 창. ①이 연결된 항목 건수 상자, ②가 삭제 버튼을 가리킵니다." caption="① 연결된 항목 ② 삭제" />

<Success>
프로그램 목록으로 이동하고, 목록 위에 `프로그램 삭제 요청을 처리했습니다` 안내가 나옵니다. 처리 결과에 따라 항목별 건수나 `목록에서 더 이상 표시되지 않습니다.`가 표시됩니다. 확인 창의 건수와 처리 결과의 건수는 다를 수 있습니다. 목록에서 프로그램이 제외됐는지 확인하세요. 이 안내는 잠깐 떴다 사라지는 알림이 아니라 목록 위에 계속 남아 있습니다.
</Success>

<Recover title="삭제가 끝나지 않을 때">
- `삭제 범위를 확인하지 못했습니다. 다시 시도해 주세요.` 창을 닫고 `프로그램 삭제`를 다시 누르세요.
- `삭제 범위가 변경되었습니다. 내용을 확인한 뒤 삭제를 다시 눌러 주세요.` 그사이 데이터가 늘거나 줄었습니다. 바뀐 건수를 읽고 다시 판단하세요.
- `프로그램 삭제 실패`: 제목 아래에 사유가 나옵니다. 서버 장애면 `요청을 처리하지 못했습니다. 잠시 후 다시 시도해 주세요.`, 연결이 끊기면 `프로그램 전체를 삭제하지 못했습니다. 잠시 후 다시 시도해 주세요.`입니다. 먼저 목록에서 프로그램이 제외됐는지 확인하고, 그대로 있으면 다시 시도하세요.
</Recover>
