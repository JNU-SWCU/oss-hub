`시스템 상태` 화면에서는 저장소 활동의 수집 상태와 데이터 기준 시각을 확인합니다. 학생 활동 숫자가 멈춰 있거나 이상해 보일 때 먼저 여는 화면입니다. 관리자만 열 수 있습니다.

수집은 자동으로 돌아갑니다. 평소에는 이 화면을 볼 일이 없고, 숫자가 이상하다는 문의가 오면 엽니다.

## 수집 상태 읽기

<Steps>
1. 왼쪽 `관리자` 묶음에서 `시스템 상태`를 엽니다.
2. 위쪽 `수집 상태` 카드의 배지를 봅니다. 아래 둘째 그림의 ①이 배지입니다.
3. 배지가 `정상`이 아니면 배지 아래의 설명 문장을 읽습니다.
</Steps>
<Shot src="admin/status-full.webp" alt="시스템 상태 전체 화면. 위쪽에 수집 상태 카드, 오른쪽 위에 지금 수집 실행 버튼, 아래에 여러 카드가 있고 ①이 지금 수집 실행 버튼을 가리킵니다." caption="전체 화면. ①은 뒤에서 설명하는 `지금 수집 실행`" />
<Shot src="admin/status-collection-state.webp" alt="수집 상태 카드. ①이 실패 배지를 가리키고, 아래에 재시도를 기다리는 항목이 있다는 설명이 있습니다." caption="① 실패 배지와 설명" />

배지는 `정상`, `지연`, `부분 진행`, `실패`, `추적 대상 없음` 중 하나입니다. 카드에는 `이번 전체 순회 시작`, `최근 전체 순회 완료`, `다음 주기 예상` 시각도 나옵니다.

### `사업단 관리자에게 알려 주세요`는 누구에게 하는 말인가요

수집 상태가 `실패`일 때는 이런 설명이 나옵니다.

> 재시도를 기다리는 수집 항목이 있습니다. GitHub 호출 한도가 풀리면 다음 주기에 자동으로 다시 시도합니다. 아래 ‘가장 오래된 재시도 대기’ 시각이 하루 넘게 그대로면 사업단 관리자에게 알려 주세요.

이 문구는 일반 사용자를 위한 것인데 관리자 화면에도 그대로 나옵니다. 관리자가 자신에게 알릴 필요는 없으니 아래 순서로 직접 확인합니다.

<Steps>
1. `데이터 최신성` 카드에서 `가장 오래된 재시도 대기` 시각을 봅니다. 이 시각이 바뀌고 있으면 수집이 진행 중입니다. 하루 넘게 그대로면 멈춘 것입니다.
2. `수집 대상 상세`에서 어느 저장소가 `재시도 대기`나 `부분`인지 찾습니다.
3. 아래 [지금 수집 실행](#지금-수집-실행)에서 수집을 다시 시작해 봅니다.
4. 그래도 풀리지 않으면 `수집 앱 설치·권한 확인` 안내를 따릅니다. 이 안내는 아래 표의 `추적 대상 없음`과 `지연` 행에 있습니다.
</Steps>
<Shot src="admin/status-freshness.webp" alt="데이터 최신성 카드. 데이터 기준 시각, 완료 항목 중 가장 오래된 실행 시각, 가장 오래된 재시도 대기 시각이 나열됩니다." caption="데이터 최신성 카드" />

멈춘 상태가 이어질 때 서비스 운영 담당자나 개발 담당자에게 전달하는 절차는 화면에 나와 있지 않습니다. <Verified status="policy" />

배지는 아래 순서로 정해집니다. 위에서부터 먼저 맞는 것이 표시됩니다.

| 배지 | 뜻 | 화면 설명 |
| --- | --- | --- |
| `추적 대상 없음` | 수집할 저장소가 아직 없습니다. | 사업단 GitHub 조직에 수집 앱이 설치돼 있는지, 저장소가 등록돼 있는지 확인하라고 안내합니다. |
| `실패` | 재시도를 기다리는 수집 항목이 있습니다. | 위의 호출 한도 설명 |
| `부분 진행` | 일부 저장소의 수집이 아직 끝나지 않았습니다. | `활동 종류별 수집`의 `부분·대기` 수를 보고, 다음 수집 주기 뒤에도 줄지 않으면 알리라고 안내합니다. |
| `지연` | `데이터 기준 시각`이 90분보다 오래됐습니다. | `데이터 기준 시각`을 확인하고, 이어지면 수집 앱의 설치·권한을 점검하라고 안내합니다. |
| `정상` | 위 경우에 해당하지 않습니다. | 없음 |

`실패` 설명에는 늘 GitHub 호출 한도 이야기가 나오지만 실제 원인은 그것만이 아닙니다. 재시도 대기 항목이 하나라도 있으면 `실패`가 되므로, 원인은 `수집 대상 상세`의 칸에 붙은 이름으로 확인하세요.

## 카드별로 보는 곳

- `활동 종류별 수집`: `완료 11 / 17개 (65%)`처럼 수집이 끝난 비율을 보여 줍니다. 범례는 `완료`, `과거 활동 수집 중`, `부분·대기`, `재시도 대기`입니다.
- `데이터 최신성`: `데이터 기준 시각`은 수집 항목 전체에서 가장 최근에 실행된 시각입니다. 바로 아래 `완료 항목 중 가장 오래된 실행 시각`은 별도 값이고, `가장 오래된 재시도 대기`는 재시도 대기 항목이 있을 때만 나옵니다.
- `수집 대상 상세`: 저장소마다 Commit, PR, Release, Issue 수집 상태를 `완료`, `과거 활동 수집 중`, `부분`, `재시도 대기`로 보여 줍니다. 위쪽에 `문제 2 / 전체 4`처럼 문제 있는 수와 전체 수가 나옵니다.
- `최근 수집 활동`: 조직과 외부 범위로 나뉜 실행 기록입니다. 상태는 `전체 순회 완료`, `수집 한도에 도달`, `진행 중`, `연결 즉시 수집`, `연결 즉시 수집 실패` 중 하나로 나옵니다. 행마다 새로 저장한 건수가 `Commit 3 · PR 1 · Release 0 · Issue 0`처럼 붙고, `저장소 3/3`은 처리한 저장소 수와 시도한 저장소 수입니다.
  - `신규 데이터 없음`: 새로 저장한 활동이 없을 때 건수 대신 나옵니다. 그 시간에 저장할 새 활동이 없었다는 뜻이고, 평소 운영에서도 자주 보입니다.
  - `아직 기록된 수집 활동이 없습니다` / `다음 수집 주기부터 쌓입니다.`: 기록이 아직 없는 상태입니다.
- `외부 저장소 수집`: 학생 개인 저장소 수집입니다. 대상이 없으면 `수집 대상 학생 개인 저장소가 없습니다`가 나옵니다. 외부 수집은 조직 수집과 함께 매시 정각에 실행하도록 설정되어 있습니다.

<Shot src="admin/status-targets.webp" alt="수집 대상 상세 표. 저장소와 프로그램 열, Commit과 PR과 Release와 Issue 열이 있고 칸마다 상태 배지가 있습니다." caption="수집 대상 상세" />

`수집 대상 상세` 표는 화면이 좁으면 오른쪽 열이 잘립니다. 표를 옆으로 밀거나 창을 넓혀서 보세요.

문제가 있는 칸에는 원인이 이런 이름으로 붙습니다. `GitHub 연결 실패`, `응답 형식 오류`, `페이지네이션 오류`, `요청 시간 초과`, `GitHub 호출 한도 초과`, `수집 연동 앱 인증 실패`, `저장소 접근 권한 없음`, `저장소를 찾을 수 없음`, `GraphQL 응답 오류`, `수집 실패`.

## 지금 수집 실행

수집은 정해진 주기로 자동으로 돌지만, 급할 때 바로 시작할 수 있습니다. 오른쪽 위 `지금 수집 실행`을 누르면 요청이 접수됐다는 알림이 뜹니다. 수집이 끝나는 데는 시간이 걸리므로 `최근 수집 활동`이 바뀔 때까지 기다리세요. 버튼을 여러 번 누를 필요는 없습니다.

버튼이 회색이고 `수집 중` 배지가 보이면 이미 수집이 돌고 있습니다. 끝난 뒤 다시 누르세요. 요청을 보내는 동안에는 잠깐 `실행 요청 중…`이 보입니다.

<Success>
`수집 요청을 보냈습니다` / `수집 요청을 접수했습니다.`가 나오고, [감사 로그](/oss-hub/admin/audit-log/)에 `수집 실행`이 남습니다. 수집은 뒤에서 돌기 때문에 `최근 수집 활동`의 새 실행은 바로 보이지 않을 수 있습니다. 시간을 두고 새로 고쳐 확인하세요.
</Success>

<Recover title="실행되지 않거나 화면이 안 열릴 때">
- `수집을 시작하지 못했습니다` / `수집을 시작하지 못했습니다. 잠시 후 다시 시도해 주세요.`: 잠시 뒤 다시 누르세요.
- `저장소 전환 작업이 진행 중이라 지금은 수집을 시작할 수 없습니다. 전환이 끝난 뒤 다시 시도해 주세요.`: 저장소 전환이 끝나기를 기다립니다.
- `시스템 상태를 불러오지 못했습니다`: 화면을 새로 고치세요.
- `최신 상태를 불러오지 못했습니다`: `상태 다시 불러오기`를 누르세요.
- 배지가 `정상`이 아니면 `수집 앱 설치·권한 확인` 안내에 따라 사업단 GitHub 조직의 Settings 아래 GitHub Apps에서 수집 앱이 설치돼 있고 권한이 있는지 확인하세요.
</Recover>
