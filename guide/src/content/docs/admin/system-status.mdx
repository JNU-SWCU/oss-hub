`시스템 상태` 화면에서는 저장소마다 마지막으로 수집에 성공한 시각을 확인합니다. 학생 활동 숫자가 멈춰 있거나 이상해 보일 때 먼저 여는 화면입니다. 관리자만 열 수 있습니다.

수집은 매시 정각에 자동으로 돌고, 일요일 새벽 3시에는 전체를 다시 읽습니다. 평소에는 이 화면을 볼 일이 없고, 숫자가 이상하다는 문의가 오면 엽니다.

## 수집 상태 읽기

<Steps>
1. 왼쪽 `관리자` 묶음에서 `시스템 상태`를 엽니다.
2. 위쪽 `수집 상태` 카드의 배지를 봅니다.
3. 배지가 `정상`이 아니면 배지 아래의 설명 문장을 읽고, `수집 대상 상세`에서 `지연`인 저장소를 찾습니다.
</Steps>
<Shot src="admin/status-full.webp" alt="시스템 상태 전체 화면. 위쪽에 수집 상태 카드와 데이터 최신성 카드, 오른쪽 위에 지금 수집 실행 버튼, 아래에 수집 대상 상세 표가 있습니다." caption="전체 화면" />

배지는 `정상`, `지연`, `추적 대상 없음` 중 하나입니다. 카드에는 `추적 저장소`와 `지연 저장소` 수, `다음 주기 예상` 시각도 나옵니다.

배지는 아래 표의 위쪽부터 차례로 따져 정해지고, 먼저 맞는 배지 하나가 표시됩니다.

| 배지 | 뜻 | 화면 설명 |
| --- | --- | --- |
| `추적 대상 없음` | 수집할 저장소가 아직 없습니다. | 사업단 GitHub 조직에 수집 앱이 설치돼 있는지, 저장소가 등록돼 있는지 확인하라고 안내합니다. |
| `지연` | 마지막 수집 성공이 2시간보다 오래된 저장소가 하나 이상 있습니다. | `수집 대상 상세`에서 지연된 저장소를 확인하고, 다음 수집 주기 뒤에도 그대로면 수집 앱의 설치·권한을 점검하라고 안내합니다. |
| `정상` | 위 경우에 해당하지 않습니다. | 없음 |

한 번 실패한 저장소는 따로 기다리지 않고 다음 정각 수집에서 다시 시도합니다. 한 번 실패하면 다음 정각 수집 직전 몇 분 동안 `지연`으로 보일 수 있고, 그 수집이 성공하면 `정상`으로 돌아옵니다. 또 실패하면 `지연`이 이어집니다.

멈춘 상태가 이어질 때 서비스 운영 담당자나 개발 담당자에게 전달하는 절차는 화면에 나와 있지 않습니다. <Verified status="policy" />

## 카드별로 보는 곳

- `데이터 최신성`: `마지막 수집 성공`은 조직 저장소 중 가장 최근에 수집이 성공한 시각과 그 나이입니다(`3시간 전`처럼).
- `수집 대상 상세`: 팀에 등록한 저장소마다 `마지막 수집 성공` 시각과 상태를 `정상`, `지연`, `수집 전`으로 보여 줍니다. 지연된 저장소가 맨 위에 오고, 위쪽에 `지연 1 / 전체 5`처럼 지연된 수와 전체 수가 나옵니다. 조직에 있다는 이유만으로 저장소를 자동 등록하거나 수집하지 않습니다.
- `외부 저장소 수집`: 학생 개인 저장소 수집입니다. 대상이 있으면 추적 수와 `마지막 수집 성공` 시각이 나오고, 대상이 없으면 `수집 대상 학생 개인 저장소가 없습니다`가 나옵니다. 외부 수집은 조직 수집과 함께 매시 정각에 실행하도록 설정되어 있습니다.

<Shot src="admin/status-targets.webp" alt="수집 대상 상세 표. 저장소, 프로그램, 마지막 수집 성공, 상태 열이 있습니다." caption="수집 대상 상세" />

`수집 대상 상세` 표는 화면이 좁으면 오른쪽 열이 잘립니다. 표를 옆으로 밀거나 창을 넓혀서 보세요.

## 지금 수집 실행

수집은 정해진 주기로 자동으로 돌지만, 급할 때 바로 시작할 수 있습니다. 오른쪽 위 `지금 수집 실행`을 누르면 요청이 접수됐다는 알림이 뜹니다. 수집이 끝나는 데는 시간이 걸리므로 `마지막 수집 성공`이 바뀔 때까지 기다리세요. 버튼을 여러 번 누를 필요는 없습니다.

버튼이 회색이고 `수집 중` 배지가 보이면 이미 수집이 돌고 있습니다. 끝난 뒤 다시 누르세요. 요청을 보내는 동안에는 잠깐 `실행 요청 중…`이 보입니다.

<Success>
`수집 요청을 보냈습니다` / `수집 요청을 접수했습니다.`가 나오고, [감사 로그](/oss-hub/admin/audit-log/)에 `수집 실행`이 남습니다. 수집은 백그라운드에서 돌기 때문에 `마지막 수집 성공`은 바로 바뀌지 않을 수 있습니다. 시간을 두고 새로 고쳐 확인하세요.
</Success>

<Recover title="실행되지 않거나 화면이 안 열릴 때">
- `수집을 시작하지 못했습니다` / `수집을 시작하지 못했습니다. 잠시 후 다시 시도해 주세요.` 잠시 뒤 다시 누르세요.
- `시스템 상태를 불러오지 못했습니다`: 화면을 새로 고치세요.
- `최신 상태를 불러오지 못했습니다`: `상태 다시 불러오기`를 누르세요.
- 배지가 `정상`이 아니면 `수집 앱 설치·권한 확인` 안내에 따라 사업단 GitHub 조직의 Settings 아래 GitHub Apps에서 수집 앱이 설치돼 있고 권한이 있는지 확인하세요.
</Recover>
