`팀 상세`는 한 팀의 구성원, 저장소, 활동, 검토 이력을 모아 보여 주는 화면입니다. 팀 관리 목록([팀 신청 승인하거나 반려하기](/oss-hub/staff/decide-application/))에서 팀 이름을 누르면 열립니다. 목록으로 돌아갈 때는 `← 참여 팀으로`를 누릅니다.

## 팀 정보 확인하기

<Steps>
1. 위에서부터 `프로젝트 저장소`, `팀원`, `팀 활동`이 나옵니다. `검토 이력`이 보이면 눌러서 펼칩니다.
2. 팀 이름은 제목 옆 연필로 바꿉니다. 오른쪽 위 `신청 상태`로 이 화면에서 바로 판정할 수도 있습니다.
3. `팀원` 카드에서 인원과 팀장을 확인합니다. 수집 기록이 있으면 팀원별 `최근 2주 커밋`도 나옵니다. `팀원 초대`를 누르거나 각 행의 메뉴에서 `팀장 변경`, `팀에서 제외`, `초대 취소` 등 그 행에 맞는 작업을 고릅니다.
</Steps>

## 저장소 확인하고 주소 바꾸기

`프로젝트 저장소`에서 저장소 이름을 누르면 GitHub에서 열립니다. 정보가 있으면 이름 아래에 `기본 브랜치`와 `마지막 수집`이 나옵니다. 아직 연결하지 않았다면 `연결된 저장소가 없습니다.`가 보입니다.

교직원은 승인된 팀의 저장소 주소를 프로그램이 끝나기 전까지 바꿀 수 있습니다. 그 밖의 경우 `변경` 버튼이 비활성화되고 `승인된 팀만 프로그램 종료 전까지 변경할 수 있습니다.`가 나옵니다.

주소를 교체하면 이전 저장소의 OSS Hub 등록 정보와 수집 기록을 삭제하고 새 저장소를 연결합니다. 이전 URL과 삭제 건수는 시스템 이력에 기록되며, GitHub 원본 저장소는 유지됩니다.

<Steps>
1. `프로젝트 저장소`의 ② `변경`을 누릅니다. 같은 카드 안에 `저장소 주소` 입력칸이 열립니다.
2. 새 GitHub 저장소 주소를 입력하고 `저장`을 누릅니다. 저장하면 `저장소 변경을 저장했습니다.`가 나옵니다.
3. 저장하지 않으려면 `취소`를 누릅니다. 주소를 수정했다면 확인 창에서 `변경사항 버리기`를 누릅니다.
</Steps>
<Shot src="staff/team-detail.webp" alt="프로젝트 저장소 카드. ②가 변경 버튼을 가리킵니다." caption="② 변경" />

① `변경 이력`은 처음에 접혀 있고, 조회할 수 있는 건수가 있으면 버튼에 표시됩니다. 버튼을 처음 펼칠 때 목록을 불러옵니다. 각 항목에서 변경 날짜, 변경한 사람의 GitHub 계정, 이전 저장소와 새 저장소를 확인합니다. `변경 이력 더 보기`가 있으면 눌러서 추가 기록을 불러옵니다. 이 목록은 신청 판정을 기록하는 `검토 이력`과 별개입니다.

<Shot src="staff/team-repo-history.webp" alt="프로젝트 저장소 카드에 이전 저장소에서 새 저장소로 바뀐 기록이 펼쳐져 있습니다. ①이 변경 이력 건수를 가리킵니다." caption="① 변경 이력 건수와 펼친 목록" />

## 활동 그래프 읽기

`팀 활동`은 연결한 저장소에서 모은 기록입니다. 아래 안내는 오류가 아니라 상태입니다.

- `아직 연결한 저장소가 없습니다`: 저장소를 연결하지 않았습니다. `프로젝트 저장소`에서 연결합니다.
- `첫 수집을 기다리는 중입니다`: 수집이 끝나면 그래프가 그려집니다. 기다리면 됩니다.
- `최근 수집에 실패했습니다`: 마지막 수집 날짜까지의 활동만 보입니다. 잠시 뒤 다시 확인하세요.
- `아직 모은 활동이 없습니다. 잠시 후 다시 확인해 주세요.` 수집은 됐지만 기록이 없습니다.

수집은 팀에 등록한 저장소를 대상으로 매시 정각에 시작합니다. `프로젝트 저장소`의 `마지막 수집`은 마지막으로 수집을 마친 시각입니다. 최근에는 `방금 전`처럼 경과 시간으로 보일 수 있습니다. 저장소마다 간격을 따로 정할 수는 없습니다.

## 저장소 공개하기

`프로젝트 저장소` 안의 `저장소 공개` 카드에서는 승인된 팀의 저장소를 GitHub에서 공개로 바꿉니다. 이 카드는 프로그램이 발급한 저장소에만 나옵니다. 팀이 직접 등록한 저장소에는 나오지 않습니다. 학생이 낸 서류 판정과는 별개의 작업입니다. 공개로 바꾸면 누구나 볼 수 있으니 공개해도 되는지 확인한 뒤 진행하세요.

<Steps>
1. `저장소 공개` 카드의 `PRIVATE`/`PUBLIC` 표시로 현재 상태를 봅니다.
2. `공개 조건을 모두 충족해 공개할 수 있습니다.`가 보이면 `GitHub 저장소 공개 전환`을 누릅니다.
3. 공개되면 `공개 저장소 열기`가 나타납니다.
</Steps>

버튼이 흐리면 조건이 아직 맞지 않은 것입니다. 카드에 이유가 나옵니다.

- `저장소 생성이 아직 끝나지 않았습니다. 생성이 끝난 뒤 이 화면을 새로고침해 주세요.`
- `이 신청은 저장소 공개 예정이 "아니요"입니다. 제출 이후에는 바꿀 수 없어 이 저장소는 공개 대상이 아닙니다.`
- `프로그램이 아직 종료되지 않아 공개할 수 없습니다. 프로그램 설정에서 종료일을 확인해 주세요 — 종료일이 비어 있으면 종료되지 않은 것으로 봅니다.`
- `모든 필수 마일스톤의 승인이 필요합니다.`

이유는 여러 개가 함께 나올 수도 있습니다. 하나를 해결한 뒤 남은 이유를 다시 확인하세요.

<Shot src="staff/review-publish-blocked.webp" alt="팀 상세의 저장소 공개 카드. ①이 모든 필수 마일스톤의 승인이 필요합니다 안내를 가리킵니다." caption="① 공개 조건이 아직 맞지 않을 때" />

OSS Hub에는 공개한 저장소를 다시 비공개로 돌리는 기능이 없습니다.

## 팀 삭제하기

화면 맨 아래 `위험 영역`의 `팀 삭제`로 팀을 지웁니다. `팀을 삭제할까요?` 창의 ① `삭제될 데이터`에서 지원서, 팀원, 제출물 같은 삭제 범위를 확인합니다. 저장소가 연결돼 있으면 ②처럼 OSS Hub의 저장소 등록 정보와 수집 기록도 함께 삭제하며 GitHub 원본 저장소는 유지됩니다. 필요하면 `팀원에게 보낼 안내 (선택)`을 적고 ③ `삭제`를 누릅니다. 지운 팀과 수집 기록은 되돌릴 수 없습니다.

<Shot src="staff/team-delete-confirmation.webp" alt="팀을 삭제할까요? 확인 창. ①이 삭제될 데이터 개수를, ②가 저장소 등록 정보와 수집 기록 삭제·GitHub 원본 유지 안내를, ③이 삭제 버튼을 가리킵니다." caption="① 삭제될 데이터, ② 저장소 안내, ③ 삭제" />

<Success>
팀원 변경은 `팀원` 목록에, 저장소 주소 변경은 `프로젝트 저장소`와 `변경 이력`에 반영됩니다.
</Success>

<Recover title="바꿀 수 없을 때">
- 저장소를 바꿀 수 없으면 팀이 승인되었는지, 프로그램이 끝나지 않았는지 확인하세요. 저장 결과를 확인할 수 없다는 안내가 나오면 `다시 불러오기`로 현재 주소를 확인한 뒤 다시 저장하세요.
- `GitHub 저장소 공개 전환에 실패했습니다.`, `저장소를 공개 전환하지 못했습니다.` 잠시 뒤 다시 누르세요. 반복되면 관리자에게 [시스템 상태](/oss-hub/admin/system-status/) 확인을 요청하세요.
- 그래프가 오래 비어 있으면 위 `활동 그래프 읽기`에서 현재 상태를 확인하세요.
</Recover>
