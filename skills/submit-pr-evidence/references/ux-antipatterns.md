# UX 안티패턴 체크리스트

화면을 건드린 PR을 열기 전에, 그리고 화면 티켓을 쓰기 전에 통과시켜야 하는 열여섯 항목이다.
UX를 배운 적이 없어도 안티패턴 이름을 몰라도 지켜지도록 각 항목을 **답이 이미 정해진 질문**으로 적었다.
넷은 세면 끝나고, 나머지 열둘은 화면을 열어 질문을 읽으면 끝난다.

근거는 [Nielsen의 10 usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)와 문서 끝의 [참고](#참고)다.
원칙 자체를 여기 옆겨 적지 않고, OSS Hub 화면에서 실제로 관찰된 형태로만 좁힌다.

## 왜 이 목록이 생겼나

제출 현황 화면이 한 뷰포트 안에서 이렇게 그려졌다.

```text
[통계]  제출 0/N │ 미제출 N건 │ 전체 미제출 5팀 │ 지각 0건
[필터]  전체 5팀 │ 미제출 포함 5팀 │ 전체 미제출 5팀
[캡션]  이 페이지 5건(전체 5건) 중 5건 표시
```

`전체 미제출 5팀`이 통계와 필터에 **글자 그대로 두 번** 있고, `전체`는 세 라벨에서 각각 모든 **팀**·모든 **서류**·모든 **건**을 뜻한다.
만든 사람은 두 컴포넌트를 따로 쓰느라 둘이 한 화면에 같이 선다는 사실을 보지 못했고, 자동 검증은 전부 통과했다.
사람의 주의력에 기대는 규칙은 이렇게 조용히 새므로, 셀 수 있는 것은 센다.

## A. 세면 끝나는 넷

배포 화면을 열고 devtools 콘솔에 아래를 붙여 넣는다.
저장소 코드에 의존하지 않으므로 어느 환경에서나 그대로 돈다.

숨긴 탭에서는 `offsetParent`·`getBoundingClientRect` 가 전부 0이라 가시성 판정이 무너진다.
그래서 레이아웃이 아니라 계산된 스타일만 본다 — 숨긴 탭에서도 성립한다.

```js
(() => {
  // 반응형 때문에 DOM에 두 벌 있는 내비게이션을 중복으로 세지 않는다
  const hidden = (el) => { let n = el;
    while (n && n.nodeType === 1) { const s = getComputedStyle(n);
      if (s.display === 'none' || s.visibility === 'hidden') return true; n = n.parentElement; }
    return false; };
  const vis = (el) => {
    const c = el.cloneNode(true);
    c.querySelectorAll('.sr-only,[aria-hidden="true"]').forEach((n) => n.remove());
    return (c.textContent ?? '').replace(/\s+/g, ' ').trim();
  };
  const out = [];

  // AP-1 중복 사실 — 표 본문을 뺀 요약 표면에서 같은 문구가 두 번 이상.
  const seen = new Map();
  document.querySelectorAll('dd,dt,button,h1,h2,h3,p,span,li').forEach((el) => {
    if (el.closest('tbody') || el.querySelector('dd,button,p,li')) return;
    if (hidden(el)) return;
    const t = vis(el);
    if (t.length < 4) return;
    seen.set(t, (seen.get(t) ?? 0) + 1);
  });
  for (const [t, n] of seen) if (n > 1) out.push(`AP-1 중복 사실 — 「${t}」 ${n}회`);

  // AP-8 수 반복 — 한 문장이 같은 수를 세 번 이상.
  document.querySelectorAll('p,li,caption,figcaption').forEach((el) => {
    const t = vis(el);
    const nums = t.match(/\d+/g) ?? [];
    const c = new Map();
    nums.forEach((d) => c.set(d, (c.get(d) ?? 0) + 1));
    for (const [d, n] of c) if (n >= 3) out.push(`AP-8 수 반복 — 「${t}」가 ${d}을 ${n}번`);
  });

  document.querySelectorAll('[role="group"],[role="tablist"]').forEach((g) => {
    const opts = [...g.querySelectorAll('[aria-pressed],[aria-selected],[role="tab"]')];
    // AP-4 상태 과잉표시 — 눌린 컨트롤이 시각 변형·ARIA 위에 상태를 텍스트로 또 말한다.
    opts.forEach((o) => {
      const on = o.getAttribute('aria-pressed') === 'true' || o.getAttribute('aria-selected') === 'true';
      if (on && /선택됨|선택|활성|현재/.test(vis(o))) out.push(`AP-4 상태 과잉표시 — 「${vis(o)}」`);
    });
    // AP-7 무력한 컨트롤 — 선택지의 수가 전부 같아 눌러도 결과가 같다.
    const nums = opts.map((o) => (vis(o).match(/\d+/) ?? [])[0]);
    if (opts.length > 1 && nums.every((n) => n !== undefined && n === nums[0]))
      out.push(`AP-7 무력한 컨트롤 — 선택지 ${opts.length}개가 전부 ${nums[0]}`);
  });

  console.log(out.length ? out.join('\n') : '자동 점검 4종 통과 (중복 문구·상태 과잉표시·무력한 컨트롤·수 반복)');
})();
```

| # | 이름 | 걸리는 조건 | heuristic |
| --- | --- | --- | --- |
| AP-1 | 중복 사실 | 같은 문구가 요약 표면 두 곳 이상에 그대로 있다 | #8 심미성과 미니멀 디자인 |
| AP-4 | 상태 과잉표시 | 눌린 컨트롤이 시각 변형·ARIA 위에 상태를 텍스트로 또 말한다 | #8 |
| AP-7 | 무력한 컨트롤 | 선택지의 수가 전부 같은데 화면이 그 사실을 말하지 않는다 | #6 기억보다 인지 |
| AP-8 | 수 반복 | 한 문장이 같은 수를 세 번 이상 말한다 | #8 |

출력을 PR 본문에 그대로 붙인다 — 손으로 옮겨 적지 않는다.
**통과는 승인이 아니다.** 이 넷은 판단이 필요한 넷을 보지 않으므로 통과 문구는 언제나 「자동 점검 4종에 한해」로 읽는다.

## B. 화면을 열고 읽는 넷

UX 지식을 요구하지 않는다. 아래 문장을 그대로 읽으면 답이 나온다.

### AP-2. 겹친 용어 — heuristic #4 일관성과 표준

> 이 화면에서 같은 단어가 몇 번 나오고, **각각 무엇의** 그것인가?

`전체`를 세 번 썼는데 하나는 모든 팀, 하나는 모든 서류, 하나는 모든 건이면 위반이다.
고치는 법은 수식 대상을 문구에 넣는 것이다 — `전체 5팀` → `참여 팀 5`, `전체 미제출 5팀` → `한 장도 안 낸 팀 5`.

### AP-3. 단위 혼용 — heuristic #4

> 나란히 선 수들의 **분모가 무엇인지** 화면만 보고 말할 수 있는가?

`미제출 N건` 옆에 `전체 미제출 N팀`이 서면 무엇이 건이고 무엇이 팀인지 세어 봐야 안다.
한 묶음 안에서는 단위를 하나로 맞추고, 단위가 달라야 하면 묶음을 나눈다.

### AP-5. 액션의 문장화 — heuristic #6 기억보다 인지

> 이 설명문이 사라지면 사용자가 **못 하게 되는 일**이 있는가?

있으면 그 자리는 문장이 아니라 컨트롤이어야 한다.
`빠른 필터·페이지와 무관하게 이 마일스톤의 전체 팀을 담습니다`는 「필터를 적용해 받고 싶다」는 요구를 문장으로 달랜 것이다.
NN/g [Command Links](https://www.nngroup.com/articles/command-links/)의 결론은 그대로다 — **주요 명령은 버튼이 낫다.**
설명은 컨트롤이 하는 일을 보충할 때만 쓰고 컨트롤을 대신하지 않는다.

### AP-6. 내부 용어 노출 — heuristic #2 시스템과 현실 세계의 일치

> 이 문구를 오늘 처음 온 교직원에게 소리 내어 읽어 주면 **되묻는 말**이 있는가?

`1인 팀 계속`은 되묻게 만든다 — 모든 참여가 팀이면 「1인 팀」이라는 말은 존재할 수 없고 그냥 팀이다.
저장 구조의 개념(단일 멤버 팀 레코드, seed id, enum 이름)이 문구로 새면 사용자는 제품의 내부 사정을 배워야 화면을 읽는다.

### 걸린 것을 다 「위반」으로 적지 않는다

AP-1은 **요약 표면에서 같은 사실을 두 번 말한 것**을 잡으려는 것이다.
구조적 반복은 그 대상이 아니다 — 마일스톤마다 하나씩인 섹션 제목, 기간이 여러 주에 걸쳐
달력이 주차 행마다 그리는 라벨, 안내가 비어 있는 항목이 둘이라 같은 문장이 두 번 뜨는 것.
이런 것을 위반으로 적으면 판정 표가 잡음이 되고, 진짜 중복이 그 속에 묻힌다.

콘솔이 걸어 준 것을 **하나씩 열어 보고** 어느 쪽인지 가른 뒤, 판정 표에 무엇을 보고 그렇게
판단했는지 한 조각을 적는다.

## C. 편집·상세 화면에서 관찰된 여덟

A·B가 한 화면 안의 **문구와 수**를 본다면, 이 여덟은 **구조와 동작**을 본다.
전부 2026-09 프로그램 편집·상세 화면에서 실제로 걸렸던 것이고, 자동 점검은 네 개 중 하나도 잡지 못했다.

### AP-9. 죽은 컨트롤 — heuristic #1 시스템 상태 가시성

> 누를 수 있게 생긴 것을 다 눌렀을 때, **아무 일도 일어나지 않는 것**이 있는가?

단일 마일스톤 편집기가 고를 범위가 하나뿐인데도 `aria-pressed="true"` 선택기를 그렸고, 호출부는 `onActiveIdChange={() => undefined}` 를 넘겼다.
화면은 누를 수 있다고 말했고, 스크린리더에는 눌린 버튼으로 읽혔으며, 키보드 사용자는 탭 한 칸을 잃었다.
고치는 법은 둘 중 하나다 — 실제로 동작시키거나, 선택지가 하나면 선택기를 안 그리는 것이다.
보이기만 하는 것을 회색으로 둘러 `disabled` 로 숨기는 것은 답이 아니다 — 왜 못 누르는지를 여전히 안 말하기 때문이다.

### AP-10. 사라진 기능의 잔상 — heuristic #2 시스템과 현실 세계의 일치

> 이 화면이 말하는 개념 중에 제품에서 **이미 없어진 것**이 있는가?

분류가 교과/비교과로 정리된 뒤에도 편집 화면은 「신청서 양식 · 기본 신청서 / 양식 버전 v1」을 그려 이 화면에서 바꿀 수 없다고 설명했다.
바꿀 수 없는 것을 보여 주고 바꿀 수 없다고 적는 것은 자리를 두 번 쓰는 일이다.
단, **화면에서 지우는 것과 도메인에서 지우는 것을 같은 일로 다루지 않는다** — 신청 화면이 여전히 그 양식을 조회한다면 표시만 거두고 계약은 남긴다.

### AP-11. 의미 없는 시각 — heuristic #6 기억보다 인지

> 화면에 적힌 날짜가 **시작인지 마감인지** 그 줄만 읽고 말할 수 있는가?

마일스톤 카드가 `2026년 8월 20일 23:59` 한 줄만 놓으면 그게 제출 시작인지 마감인지 알 수 없다.
`시작`·`마감` 라벨을 붙이고 범위는 범위로 보여 준다.
마감 하나만 보여 주기로 정했으면 그 사실을 라벨이 말해야 하고, 숫자 옆에 제품 내부 기준(서울/UTC)을 사용자가 유추하게 두지 않는다.

### AP-12. 뒤섞인 출처 — heuristic #4 일관성과 표준

> 이 문단을 **누가 썼는지** — 운영자인지 제품인지 — 화면만 보고 가를 수 있는가?

운영자가 쓴 마일스톤 공지와 개발자가 붙인 「항목 왼쪽 손잡이를 끌어 순서를 바꾸세요」가 같은 회색 문단으로 서 있었다.
사용자는 둘을 같은 무게로 읽고, 정작 읽어야 할 공지를 설명문으로 오해한다.
운영자가 쓴 내용은 이름 있는 영역(「운영자 공지」)으로 묶고, 제품 안내는 그 컴트롤 옆으로 보낸다.

### AP-13. 뒤집힌 노출 — heuristic #8 심미성과 미니멀 디자인

> 이 화면은 **읽을 내용**을 접어 두고 **편집 도구**를 펼쳐 두지 않았는가?

편집 화면은 제출 항목을 접어 두고, 정작 가끔 쓰는 달력을 페이지 절반에 상시 펼쳐 다른 내용을 밀어냈다.
기본값은 반대다 — **현재 상태는 보이고, 바꿀 때 여는 것은 도구**다.
무엇을 접을지는 progressive disclosure가 정한다 — 드물게 쓰는 것을 감추고 자주 보는 것을 내다.

### AP-14. 갈라진 편집 — heuristic #4

> 같은 대상을 고치는 방법이 **화면마다 다른가**?

마일스톤 하나가 「수정」 다이얼로그(이름·일정·공지)와 카드 아래 즉시 저장(제출 항목)으로 나뉘어 있었고, 그 분리를 설명하려고 「아래 제출 항목에서 관리합니다」라는 문장이 생겼다.
**구조를 설명하는 문장이 생겼다면 그건 문장이 아니라 구조가 틀렸다는 신호**다(AP-5의 반대편).
만드는 화면과 고치는 화면은 필드 구성·라벨·검증을 공유한다. 상호작용 흐름까지 복사하라는 뜻은 아니다.

### AP-15. 어깽난 저장 범위 — heuristic #3 사용자 통제와 자유

> 「저장」과 「취소」가 **어디까지** 저장하고 되돌리는지, 화면이 보여 주는 범위와 같은가?

한 편집창 안에 보이는데 일부는 즉시 저장되고 일부만 「저장」을 기다리면, 「취소」는 사용자가 생각하는 것을 되돌리지 못한다.
범위를 합치는 것이 원칙이고, 합칠 수 없다면 **합쳐진 것처럼 보이게 둘 다 내지 않는다**.
되돌릴 수 없는 결과(파일 교체·항목 삭제)는 그 사실을 반드시 말하고, 부분 저장을 사용자에게 떠넘기지 않는다.

### AP-16. 닿지 않는 본문 — heuristic #7 유연성과 효율성

> 좁은 화면·긴 내용·키보드가 올라온 상태에서 **모든 입력과 하단 버튼에 닿는가**?

제출 항목 편집기를 폼 밖 별도 스크롤 영역으로 붙였더니 본문이 79px로 눌려 마일스톤을 아예 못 고치게 됐다.
한 편집창에 **스크롤 주체는 하나**여야 하고, 머리·바닥은 고정하되 본문이 남는 높이를 가져가야 한다.
390px 폭과 낮은 높이(키보드)에서 긴 한국어 이름을 넣고 확인한다. 반복 아이콘은 44px 행동영역과 접근성 이름·tooltip을 갖춘다.

| AP-14 | 갈라진 편집 | 같은 대상을 화면마다 다른 방식으로 고친다 | heuristic #4, GOV.UK Question pages |
| AP-15 | 어깽난 저장 범위 | 저장·취소가 되돌리는 범위가 화면과 다르다 | heuristic #3, WCAG 3.3.4 |
| AP-16 | 닿지 않는 본문 | 좁은 화면·긴 내용에서 입력이나 하단 버튼에 닿지 못한다 | WCAG 2.5.8 |

## 판정 표

PR 본문과 화면 티켓에 이 표를 그대로 넣는다.
`통과`만 적힌 줄은 근거 없는 통과이므로 미통과로 본다 — 무엇을 보고 통과라고 했는지 한 조각을 적는다.

```markdown
| # | 판정 | 근거 |
| --- | --- | --- |
| AP-1 중복 사실 | 자동·통과 | 콘솔 출력 |
| AP-2 겹친 용어 | 위반 → 고침 | `전체`가 팀/서류/건 세 뜻이라 `참여 팀`·`한 장도 안 낸 팀`으로 갈랐다 |
| AP-3 단위 혼용 | 해당 없음 | 이 화면에 수 묶음이 없다 |
| AP-4 상태 과잉표시 | 자동·통과 | 콘솔 출력 |
| AP-5 액션의 문장화 | 위반 → 고침 | ZIP 범위 안내문을 지우고 「필터 적용해 받기」 버튼을 뒀다 |
| AP-6 내부 용어 | 위반 → 고침 | `1인 팀 계속` → `팀 없이 계속` |
| AP-7 무력한 컨트롤 | 자동·통과 | 콘솔 출력 |
| AP-8 수 반복 | 자동·통과 | 콘솔 출력 |
| AP-9 죽은 컨트롤 | 위반 → 고침 | 범위가 하나인데 `aria-pressed` 선택기가 있었고 핸들러가 no-op이라 선택기를 없앨다 |
| AP-10 사라진 기능의 잔상 | 해당 없음 | 이 화면이 말하는 개념이 전부 현재 제품에 있다 |
| AP-11 의미 없는 시각 | 위반 → 고침 | 마감 한 줄만 있던 카드에 `시작`·`마감` 라벨을 붙였다 |
| AP-12 뒤섞인 출처 | 위반 → 고침 | 운영자 공지를 이름 있는 영역으로 묶고 조작 안내를 컨트롤 옆으로 즌다 |
| AP-13 뒤집힌 노출 | 위반 → 고침 | 제출 항목을 기본 노출하고 달력은 수정을 누를 때 열게 했다 |
| AP-14 갈라진 편집 | 위반 → 고침 | 메타데이터와 제출 항목을 한 편집 세션으로 모으고 안내문을 없앱다 |
| AP-15 어깽난 저장 범위 | 위반 → 고침 | 즉시 저장을 없애고 저장 전 취소가 서버 변경 0이 되게 했다 |
| AP-16 닿지 않는 본문 | 위반 → 고침 | 본문 79px 붕괴를 고쳤고 390x844·390x440에서 도달을 확인했다 |
```

## 하지 않는 것

- 판단이 필요한 넷을 자동 점검으로 대신하지 않는다 — 대신하는 순간 통과가 승인으로 읽혀 사람이 봐야 할 자리가 사라진다.
- 위반을 고치지 않은 채 「알고 있음」으로 적지 않는다 — 티켓 경계 밖이면 별도 티켓으로 제안하고 그 사실을 적는다.
- 이 목록을 「참고」로 다루지 않는다 — 열여섯 줄이 다 차지 않은 PR은 증거 게이트 미통과다.
- 이 점검을 저장소 안의 헬퍼 모듈로 옆기지 않는다 — 스킬이 제품 코드에 의존하면 그 코드가 사라질 때 규칙도 같이 사라진다.
- C의 여덟을 자동화하려고 하지 않는다 — 「이 버튼은 정말 아무 일도 안 하는가」는 호출부를 읽어야 답할 수 있다.

## 참고

위 항목들의 근거다. 제품 결정과 외부 근거를 섮지 않기 위해 링크로만 둔다 — 원문 주장을 이 문서에 버전 없이 복사해 두지 않는다.
각 항목이 어떤 주장에서 온 것인지는 위 설명과 표가 가리킨다.

**일반 원칙**

- Nielsen Norman Group, [10 Usability Heuristics for User Interface Design](https://www.nngroup.com/articles/ten-usability-heuristics/) — A·B·C 전체의 바탕
- Don Norman, [Signifiers, not affordances](https://jnd.org/signifiers_not_affordances/) — AP-9. 작동하지 않는 것이 작동하는 것처럼 보이면 안 된다

**컴트롤과 설명문**

- NN/g, [Command Links](https://www.nngroup.com/articles/command-links/) — AP-5. 주요 명령은 문장이 아니라 버튼이다
- NN/g, [Icon Usability](https://www.nngroup.com/articles/icon-usability/) — 아이콘 전용 컨트롤의 조건. 주 CTA는 가시 텍스트를 유지하고 반복 컨트롤에만 쓴다
- W3C, [WAI-ARIA Authoring Practices — Button Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/) — AP-9. `aria-pressed`는 상태가 실제로 바뀔 때만 쓴는다

**구조와 흐름**

- GOV.UK Design System, [Question pages](https://design-system.service.gov.uk/patterns/question-pages/) — AP-14. 한 번에 하나씩 묻고, 같은 정보를 한 여정에서 두 번 묻지 않는다
- NN/g, [Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) — AP-13. 무엇을 접고 무엇을 낼지의 기준
- NN/g, [Wizards](https://www.nngroup.com/articles/wizards/) — 마법사는 드물게 하는 일에 맞는다. 반복하는 편집을 마법사로 만들지 않는다

**오류와 되돌림**

- NN/g, [Confirmation Dialogs Can Prevent User Errors](https://www.nngroup.com/articles/confirmation-dialog/) — AP-15. 확인창은 결과와 가역성을 말해야 한다
- NN/g, [Error Message Guidelines](https://www.nngroup.com/articles/error-message-guidelines/) — 오류는 원인과 다음 행동을 함께 말한다
- W3C, [WCAG 2.2 — 3.3.4 Error Prevention](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html) — AP-15. 되돌릴 수 없는 제출은 검토·확인·취소 중 하나를 준다

**접근성과 반응형**

- W3C, [WCAG 2.2 — 2.5.8 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) — AP-16. 반복 아이콘의 행동영역 하한
- W3C, [WCAG 2.2 — 1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) — AP-16. 좁은 화면에서 내용을 잃거나 두 방향 스크롤을 강요하지 않는다
