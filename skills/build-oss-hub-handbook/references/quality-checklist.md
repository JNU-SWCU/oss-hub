# OSS Hub handbook quality checklist

## Evidence

- [ ] Record the exact deployed release and KST verification date.
- [ ] Separate live UI observation from automated-test or code evidence.
- [ ] Mark every unverified endpoint or screenshot `확인 필요`.
- [ ] Mark unresolved access, ownership, retention, or recipient scope `정책 확인 필요`.

## Student handbook

- [ ] Login, consent, role, and profile completion.
- [ ] Program search and eligibility.
- [ ] Team creation, invitation, acceptance, and team lock timing.
- [ ] NEW repository issuance and GitHub invitation acceptance.
- [ ] OWN external repository URL connection and ownership warning.
- [ ] Application submission and approval result.
- [ ] Template download, file submission, resubmission, and status.
- [ ] Activity view and empty-repository explanation.
- [ ] Program board posts/comments and participant restriction.
- [ ] Account settings, immutable student ID, notifications, and deactivation.

## Staff handbook

- [ ] Login, role approval, and staff dashboard.
- [ ] Full program authoring wizard and edit screen.
- [ ] Milestones with and without required documents.
- [ ] Template attachment and replacement.
- [ ] Applicant detail, approval, rejection, and undo decision.
- [ ] Repository issue/status interpretation.
- [ ] Teams, activity graph, and collection delay/empty state.
- [ ] Submission status, file download, review, and decision.
- [ ] Missing-document filters, preview, manual student reminder, and staff summary.
- [ ] Automatic-versus-manual email behavior.
- [ ] Repository publication gates.
- [ ] Account settings, notification opt-in, and deactivation.

## Administrator handbook

- [ ] Access-request inbox and approval/rejection.
- [ ] Role and account-status management.
- [ ] Reactivation after self-deactivation.
- [ ] Audit log and system status.
- [ ] Program deletion blockers and no-force-delete warning.
- [ ] Staff-equivalent program operations where applicable.
- [ ] Account settings, notification opt-in, and administrator lockout warning.
- [ ] Current global staff/admin access and recipient-scope policy warnings.

## Screenshots and privacy

- [ ] Use the current deployed UI and add a caption.
- [ ] One action or decision per image.
- [ ] No passwords, tokens, private emails, real student IDs, real submissions, or private repository details.
- [ ] Replace short-lived signed URLs with Notion-hosted uploads.
- [ ] Add an exact `확인 필요: 최신 화면 사진` marker where a safe image is unavailable.

## Notion structure

- [ ] Role-specific title and short first-time-user introduction.
- [ ] Five-minute quick start.
- [ ] Task-based table of contents.
- [ ] Exact visible labels in numbered steps.
- [ ] Success signal and common failure recovery for each major task.
- [ ] Working child-page links and no duplicate chapters.
- [ ] Footer on every page: `마지막 확인일: YYYY-MM-DD (KST) · 배포본 vX.Y.Z`.

## Handoff

- [ ] Fetch updated pages and verify content after writing.
- [ ] List completed pages and remaining `확인 필요` sections.
- [ ] Attach a separate product-problem report.
- [ ] Confirm that no product code or live product data was modified by the skill.
