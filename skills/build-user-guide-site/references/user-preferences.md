# 사용자가 정한 취향과 원칙

이 사이트는 아래 요청에서 출발했습니다. 판단이 갈리면 이 문서가 먼저입니다. 따옴표 안은 사용자의 말을 그대로 옮긴 것입니다.

## 원칙으로 옮기면

| 요청 | 지켜야 할 것 |
|---|---|
| 1 | 독자는 학생, 관리자, 교직원, 로그인 전 방문자입니다. 방문자는 별도 절을 두지 않고 소개 절의 "로그인 전에 볼 수 있는 화면"에서 다룹니다. 모든 단계에 실제 화면이 붙습니다. |
| 2 | 호스팅은 GitHub Pages입니다. 주소는 `https://jnu-swcu.github.io/oss-hub/`, base는 `/oss-hub`입니다. |
| 3 | 읽고 따라 하면 실제로 쓸 수 있어야 합니다. 서비스 소개 → 시작하기 → 관리자 → 학생 → 교직원 → FAQ 순서이며 역할 순서는 바꾸지 않습니다. 윤문은 필수 단계이고 토큰을 아끼지 않습니다. |
| 4 | 오케스트레이터는 판단, 검수, 커밋만 합니다. 캡처, 집필, 사실 확인, 시각 검수, 윤문은 서브에이전트에게 맡기고 가능한 한 병렬로 돌립니다. |
| 5, 11 | 화면을 가리지 않습니다. 11번 요청이 5번의 블러를 대체했습니다. 개인정보는 예시 데이터로 애초에 없애고, 설명은 번호가 붙은 빨간 박스로 더합니다. |
| 6 | Aside는 독자 시험(완성된 가이드를 처음 읽는 사람처럼 격리 스택에서 따라 해 보기)과 배포 주소 확인에만 씁니다. 캡처에는 쓰지 않습니다. 로그인된 실제 브라우저라 실제 데이터가 찍힐 수 있기 때문입니다. |
| 7 | 마일스톤마다 커밋하고 푸시하고 Pages 실행을 확인합니다. 한꺼번에 크게 올리지 않습니다. 사용자는 Pages를 보며 진행 상황을 봅니다. |
| 8 | 빌드와 배포는 워크플로가 하므로 사람이 손으로 배포하지 않습니다. |
| 9 | 글꼴은 제품과 같은 Pretendard입니다(9번 요청이 8번의 Noto Sans KR을 대체). 본문 라벨은 칩이나 고정폭이 아니라 굵은 글자로 보여 줍니다. 제목은 작고 단정하게(문서 h1 2rem, 랜딩 최대 3.5rem), 한국어 줄바꿈은 `keep-all`입니다. 이미지는 원본 크기보다 늘리지 않습니다. |
| 10 | 어느 화면의 어디인지 알 수 있게 찍습니다. 글자나 컨트롤이 가장자리에 붙거나 잘리면 다시 찍습니다. |
| 12 | 에이전트 운용은 Anthropic 공식 글과 문서를 근거로 하고 `orchestration.md`에 출처와 함께 적습니다. 비용을 줄이는 지침이 품질을 낮추면 3번의 토큰 기준이 먼저입니다. |
| 13 | 범위(`update`, `full`)와 강도(`low`, `mid`, `high`)로 부릅니다. 기본은 `update mid`입니다. `high`는 3번의 품질 기준을 그대로 지키고, `low`는 문구만 맞추는 빠른 길입니다. |

## 같이 정해진 기준

- 이미지를 오케스트레이터가 직접 보기 전에는 커밋하지 않습니다. 에이전트 보고는 부풀려질 수 있으므로 파일 수정 시각과 이미지를 직접 확인합니다.
- 본문에 이름, 아이디, 이메일, 학번, localhost, 시드, 합성 데이터라는 말을 쓰지 않습니다.
- 제품 결함을 본문에 "버그"라고 쓰지 않습니다. 현재 동작과 우회 방법을 쓰고 결함은 본문에 쓰지 않고 사용자에게 따로 알립니다.
- 화면에 나온 라벨을 백틱으로 그대로 씁니다.
- 첫 화면은 넓은 폭에서 제목과 소개를 두 칸으로 놓고, 모바일 목업은 글자가 읽히도록 확대해 잘라 보여 줍니다. 좁은 화면에도 메뉴를 둡니다.
- 문서 표는 넓은 폭에서 본문 칸을 꽉 채웁니다.
- 캡션은 이미지 안 제목을 되풀이하지 않고, 무엇을 볼지 적습니다.
- 한국어는 "-합니다"체이고 번역투와 AI 투를 걷어 냅니다. 자세한 규칙은 `writer-brief.md`와 `audit-and-polish.md`에 있습니다.
- 이 스킬은 가이드 사이트만 책임집니다. 다른 스킬이 맡은 일을 옮겨 적지 않습니다. 윤문은 `humanize-korean`을 쓰기만 합니다.
