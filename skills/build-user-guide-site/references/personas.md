# 합성 데이터와 페르소나 계획

캡처용 DB는 실제 사람이 없는 합성 데이터만 담습니다. 이 문서는 이름, 로그인, 학번을 적지 않고 역할과 상태로만 설계를 적습니다. 실제 값은 준비 SQL에 두고 저장소 밖(`<G>`)에서 관리합니다.

## 원칙

- 모든 이메일은 `.example` 예약 도메인, 이름은 합성 이름, 학번과 교직원 번호는 합성 값입니다.
- 화면을 가리지 않으므로 보이는 값은 모두 자연스러운 예시여야 합니다. `테스트` 같은 어색한 이름이나 합성 티가 나는 값을 남기지 않습니다.
- 아이디와 조직, 저장소 이름은 실제 GitHub 계정과 겹치면 안 됩니다. 넣기 전에 `gh api users/<login>`과 `gh api repos/<owner>/<repo>`가 404인지 확인합니다. 겹치면 실제 사람을 가짜 데이터에 묶게 됩니다.
- 화면에 영문 코드 같은 날것의 값이 보이면 먼저 준비 SQL의 값이 제품 코드가 아는 값인지 확인합니다. 제품 쪽 표시 표에 없는 값을 넣으면 화면이 고장 난 것처럼 찍힙니다.
- 준비 SQL은 여러 번 돌려도 같은 결과가 나오도록 멱등으로 씁니다. 실행 명령은 `stack.md`에 있습니다.
- 데이터 안의 "오늘"은 촬영 기준일로 고정해 두고(이 사이트는 2026-11-02 KST) 날짜가 어긋나 보이지 않게 마일스톤 날짜를 정합니다.
- 저장소 조직은 `JNU-SWCU`로 둡니다. 저장소 이름은 예시이며 화면에 그대로 보입니다.
- 시드는 `SEED_PROFILE=auth`와 `SEED_PROFILE=demo`로 `prisma db seed`를 차례로 돌려 기본 데이터를 만들고, 그 위에 준비 SQL로 가이드용 상태를 얹습니다.
- AuditLog는 추가 전용 테이블이라 고치려면 `begin; set local session_replication_role=replica; ...; commit;` 안에서 합니다. 감사 로그 metadata는 엄격히 파싱되므로 형식이 틀린 행이 있으면 목록 API가 500을 냅니다. 행을 넣을 때 형식을 지키세요. 합성 사용자를 SQL로 지우면 그 사용자가 행위자인 행도 같은 500을 내니 함께 지웁니다.

## 있어야 하는 페르소나(역할과 상태)

| 구분 | 상태 | 쓰이는 화면 |
|---|---|---|
| 관리자 | 주 관리자 1, 보조 관리자 1 | 관리자 전체 |
| 교직원 | 프로그램을 운영하는 책임 교직원 | 교직원 전체, 승인 대기 화면 |
| 교직원 | 일반 교직원(권한 회수 대상으로 쓸 수 있는 1명) | 역할 변경, 비활성화 |
| 교직원 | 이미 비활성화된 교직원(DEACTIVATED) | 비활성 상태 안내 |
| 교직원 요청 | 승인 대기, 반려(사유 포함) | 교직원 가입 신청과 처리 |
| 학생 | 팀장(공모전 팀장이면서 부트캠프 팀장 겸임) | 저장소, 제출, 팀 관리 |
| 학생 | 다른 공모전 팀의 팀장들 | 순위, 팀 목록 |
| 학생 | 팀원(순위표에서 "나"가 강조되는 사람) | 팀원 시점 |
| 학생 | 신청서가 처리된 신청자 | 신청 결과 |
| 학생 | 신청 이력이 없고 초대만 받은 학생 | 초대 수락 |
| 학생 | 역할 미선택(로그인 후 역할 선택 화면) | 가입 첫 단계 |
| 학생 | 동의 대기 | 약관 동의 |
| 학생, 교직원 | 온보딩 중 | 최초 진입 |
| 학생 | 프로필이 완성된 학생 | 설정 |
| 학생 | 순위 최상위 | 순위 |
| 학생 | 목록 페이지를 넘길 만큼의 학생 무리(반려된 신청의 팀장 포함) | 목록 페이징, 사용자 찾기 |
| 비로그인 | 로그인하지 않은 방문자 | 랜딩, `/programs`, `/ranking` |

## 프로그램 네 가지 상태

| 유형 | 상태 | 구성 |
|---|---|---|
| 공모전 | 진행 중(RUNNING) | 팀 5, 마일스톤(중간 발표, 최종), 저장소 자동 생성 켜짐 |
| 부트캠프 | 모집 중(OPEN) | 팀 2, 신청서, 대기 중인 초대 |
| 인턴십 | 예정(UPCOMING) | 이름을 바꾼 상태, 팀 없음 |
| 마일리지 | 종료(ENDED) | 종료 안내 |

## 저장소와 제출 상태

- 저장소: 공개(PUBLIC), 비공개(PRIVATE), 실패 기록이 있는 공개 저장소, 이력 채우는 중(BACKFILLING)이거나 호출 제한(오류 코드 PROVIDER_RATE_LIMITED)이면서 대기 중인 초대가 있는 저장소, 비어 있고 대기 중(PENDING)인 비공개 저장소, 외부 공개 저장소(EXTERNAL_PUBLIC).
- 제출: 승인(APPROVED), 제출됨(SUBMITTED), 반려(REJECTED), 수정 요청(CHANGES_REQUESTED) 상태가 각각 하나 이상.

## 새 페르소나를 더할 때

1. 어떤 화면에서 어떤 상태가 필요한지 한 줄로 적습니다.
2. 준비 SQL에 멱등 INSERT로 더합니다(`ON CONFLICT DO NOTHING` 등).
3. 이 표에 역할과 상태만 추가합니다. 이름과 로그인은 적지 않습니다.
4. 캡처할 때 `openAs('<login>')`로 열어 `skills/build-user-guide-site/scripts/smoke.mjs`로 먼저 점검합니다.

## 준비 SQL의 보관

준비 SQL에는 합성이라도 사람 이름과 로그인, 학번 모양의 값이 들어 있어 스킬에 싣지 않았습니다. 처음부터 다시 만들 때는 위 표를 기준으로 새로 쓰거나, 이전 작업 폴더의 SQL을 비식별화해 이 스킬에 넣는 것을 검토하세요.
