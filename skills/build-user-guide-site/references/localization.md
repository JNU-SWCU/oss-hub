# 한국어·영어 가이드

## 경로와 범위

- 기존 한국어 문서 주소와 `src/content/docs/`를 유지한다. 영어는 `/oss-hub/en/`와 `src/content/docs/en/`에 둔다. 언어를 지정하지 않은 진입점 `/oss-hub/`의 결정 규칙은 아래 절이 소유한다.
- 한국어 작업 페이지마다 같은 상대 경로의 영어 페이지를 둔다. 한국어 커스텀 랜딩 `src/pages/index.astro`에 대응하는 영어 첫 화면은 `en/index.mdx`다.
- 언어를 지정하지 않으면 `both`로 처리한다. 특정 언어만 요청했으면 그 범위를 지키고, 다른 언어에 남은 불일치는 최종 보고에 적는다.
- 제품 동작이 바뀌면 영향받은 두 언어 페이지를 같은 변경에서 갱신한다. 한 언어의 문체만 고칠 때는 다른 언어를 불필요하게 다시 쓰지 않는다.
- 영어 지원·번역 요청은 제품 diff가 없어도 수행한다. 번역만 하는 작업은 기존 가이드와 이미지를 근거로 삼으며 제품 재캡처나 격리 스택 재기동을 요구하지 않는다.

## 진입과 언어 선택

- 자동 판별은 `/oss-hub/` 진입점에서만 한다. 유효한 수동 선택(`oss-hub-guide-language`의 `ko` 또는 `en`) → `navigator.languages` 순서에서 처음 지원하는 언어 → `navigator.language` → 영어 순이다. 지역 태그는 기본 언어로 판별한다.
- 한국어 판정은 기존 루트 화면에 머무르고 영어 판정은 `/oss-hub/en/`으로 `location.replace`한다. 쿼리와 해시는 유지한다. 자동 판정과 직접 URL 방문은 수동 선택으로 저장하지 않는다.
- `/oss-hub/ko/`는 기존 한국어 랜딩을 공유하는 명시적 별칭이다. `/en/`, `/ko/`, 기존 한국어 문서 주소는 시스템 언어나 저장값으로 덮어쓰지 않는다. 기존 문서 경로를 이동하거나 전체 한국어 문서를 `/ko/` 아래에 복제하지 않는다.
- 모든 랜딩·문서에 현재 언어가 표시된 `EN · KO` 링크를 두고 좁은 화면에서도 바로 보이게 한다. 수동 선택만 저장하며 같은 문서의 대응 URL로 이동한다. 404 화면에서는 각 언어 홈으로 복구한다. 홈의 한국어 선택은 `/ko/`를 사용해 저장소를 사용할 수 없어도 자동 판별과 충돌하지 않는다.
- 언어 전환은 현재 쿼리와 해시를 그대로 보존한다. 번역된 제목의 해시를 추측해 바꾸지 않는다. 기존 앵커의 의미를 바꾸는 작업은 별도로 대응 관계를 검수한다.
- 랜딩에 `한국어 가이드`, `English guide`처럼 언어를 따로 고르는 CTA를 두지 않는다. 가이드 진입 액션은 현재 문서 언어의 `가이드 보기` / `Read the guide`로 같은 언어의 시작하기 문서를 연다. 언어 선택은 헤더가 맡는다.
- 저장소 접근 실패는 이동과 문서 읽기를 막지 않는다. 자동 이동은 루트에서 한 번만, 수동 이동은 일반 링크로 처리해 새로고침·뒤로 가기에서 재이동 루프를 만들지 않는다.

참고한 Xia 구현은 [언어 저장](https://github.com/GoBeromsu/website/blob/main/assets/main.js)과 [같은 페이지의 EN · KO 링크](https://github.com/GoBeromsu/website/blob/main/scripts/build.mjs)다. 화면의 원칙을 참고하며 이 문서의 진입·우선순위 계약이 OSS Hub의 기준이다.

## 집필

- 제목, 설명, 본문, 표, 이미지 alt·caption, 경고와 성공·복구 문구를 문서 언어로 쓴다.
- 영어는 짧은 능동 문장과 직접적인 동사를 쓴다. 역할은 Administrator, Student, Staff로 통일하고 Staff가 교원과 행정 직원을 포함함을 첫 안내에서 설명한다.
- 실제 한국어 버튼·메뉴는 백틱 안에 그대로 두고 영어 뜻을 붙인다. 화면에 없는 영어 버튼을 만들어 쓰지 않는다.
- 한국어 제품 화면 이미지는 두 언어에서 공유한다. 이미지 안 글자를 영어로 덧씌워 영어 UI처럼 보이게 하지 않는다.
- 영어 첫 안내에서 제품 UI와 캡처는 한국어이고 영어는 문서 지원임을 알린다. 글로벌 공개 문서가 다른 기관의 즉시 운영 가능성이나 현지 정책 적합성을 보증한다고 쓰지 않는다.
- 원문의 권한, 조건, 경고, 숫자, 순서, 미확인 표시를 보존한다. 번역 과정에서 발견한 제품 불일치는 따로 보고한다.
- 문서 내 링크는 같은 언어의 대응 경로로 연결한다. 언어 전환은 가능하면 현재 작업 페이지의 대응 페이지를 연다. 제목 번역으로 바뀐 앵커도 확인한다.
- `checkedCommit`, `lastChecked`, `releaseVersion`은 제품 검증 기준이다. 번역이나 문장 교정만으로 올리지 않는다.

## 검수

1. 실제 한국어 파일 목록과 영어 파일 목록을 대조해 빠진 작업 페이지를 찾는다. 랜딩 구현 차이만 예외로 둔다.
2. 영어 페이지의 한국어는 화면 라벨·고유명·설명에 필요한 인용인지 읽고 판단한다. 한글 존재만으로 번역 실패라고 판정하지 않는다.
3. 역할별 대표 페이지에서 조건·경고·번호·공유 이미지·링크가 원문과 일치하는지 대조한다.
4. 전체 사이트를 빌드하고 한국어와 영어의 내부 링크, 페이지 제목, 언어 속성, 검색 색인을 확인한다.
5. 데스크톱과 390×844 모바일에서 언어 선택기의 노출·현재 값·같은 문서 전환·쿼리와 해시 보존, 역할 사이드바, 검색, 이미지 확대, 테마 전환, 성공·복구·검증 배지와 푸터를 확인한다.
6. 실제 브라우저에서 ko/en/미지원 시스템 언어, 지원 언어 우선순위, 저장된 두 수동 선택, 직접 언어 URL, 기존 링크, 저장소 차단, 새로고침·뒤로/앞으로 가기·루프를 각각 확인한다. `cd guide && pnpm build` 뒤 `node --test guide/tests/*.test.mjs`로 결정 함수와 빌드 결과를 검사한다. 이는 실제 브라우저 검증을 대신하지 않는다.
7. 공개 배포 뒤 한국어와 영어 주소를 각각 확인한다. 로컬 빌드, PR, 병합, Pages 배포를 서로 구별해 보고한다.
