# 역할별 화면 캡처 지시서

캡처 서브에이전트에게 그대로 넘기는 문서입니다. `<ROOT>`는 저장소(워크트리) 루트, `<G>`는 저장소 밖 작업 폴더입니다(오케스트레이터가 정해서 알려 줍니다).

OSS Hub 사용자 가이드 사이트(`website/`)에 실을 실제 화면을 찍습니다. 독자는 이 가이드만 보고 실제 서비스를 쓸 수 있어야 합니다. 대충 찍은 화면은 곧바로 품질 하락입니다.

## 경로와 도구

- 스택: 격리 스택이 이미 떠 있습니다(프런트 `http://localhost:3310`, 백엔드 `http://localhost:4310`). 재시작하지 마세요. 띄우는 법은 `stack.md`.
- 캡처 라이브러리: `skills/build-user-guide-site/scripts/capture-lib.mjs`. 환경 변수 `SESSION_SECRET`(스택을 띄운 값과 같아야 함)이 필요합니다.
- 먼저 읽을 것: `personas.md`(이 폴더), `<G>/facts-<role>.md`.
- 캡처 스크립트는 `<G>/capture-<role>/`에 둡니다. 저장소에 커밋하지 않으며 워크트리에 두지 마세요. 커밋과 푸시는 하지 않습니다.
- 로그인된 실제 브라우저(예: Aside)나 브라우저 자동화 도구로 찍지 마세요. 실제 데이터가 찍힙니다. 캡처는 `capture-lib.mjs`의 합성 페르소나 세션으로만 합니다.

## 사용법

```js
import { openAs, visit, shot, clipAround, closeAll } from '<ROOT>/skills/build-user-guide-site/scripts/capture-lib.mjs';
const p = await openAs('<login>');
await visit(p, '/my-repos');
await shot(p, 'student', 'my-repos', { fullPage, clip, locator });
const clip = await clipAround(p, [p.getByRole('heading', { name: '제목' }), p.locator('tbody tr').nth(4)]);
await closeAll();
```

- `openAs(login, { width, height, dpr, theme })`: 비로그인은 `null`.
- 결과: `website/src/assets/shots/<role>/<name>.webp`. 이름은 짧은 영어 kebab-case.
- `smoke.mjs <login|anon> <path>...`로 경로가 열리는지, 개인정보나 개발 배지가 새지 않는지 먼저 점검할 수 있습니다.

## 촬영 기준

- **한 장에 한 동작.** 본문 폭은 약 760px입니다. 1280px 전체 화면은 글자가 작아지므로, 화면 위치를 알려 주는 전체 화면은 절 시작에만 쓰고 나머지는 `locator`나 `clip`으로 카드, 표, 대화상자에 맞춥니다. 대화상자는 대화상자 요소만 찍습니다.
- **잘리지 않게 찍습니다.** 독자가 "잘린 사진"으로 느끼는 경우는 네 가지입니다. 모두 다시 찍습니다.
  - 가장자리에 줄이나 카드가 반쯤 걸린 사진. 아래쪽 경계는 줄과 줄, 카드와 카드 사이에 둡니다. `clip`을 눈대중 숫자로 정하지 말고 `clipAround(page, [첫 요소, 마지막 요소])`로 요소에 맞춥니다.
  - 내용이 가장자리에 붙은 사진. 사방에 12px 이상 여백을 둡니다. `locator`로 찍으면 `shot`이 여백을 넣습니다. 둥근 카드 모서리가 잘려도 안 됩니다.
  - 어느 화면인지 모르는 사진. 표의 한 줄만, 입력칸 한 줄만 찍지 않습니다. 구역 제목이나 표 머리글까지 함께 찍습니다. 높이 100px 미만의 띠 모양 사진은 대개 여기에 해당합니다.
  - 내려 놓은 메뉴 뒤의 표 글자가 양옆으로 잘린 사진. 본문 영역 너비 전체를 찍습니다.
  - 찍은 뒤 `python3 scripts/margin-check.py`로 가장자리 여백을 잽니다. `b0`처럼 0에 가까운 값이 나오면 이미지를 열어 확인합니다. 화면 전체를 찍은 사진의 어두운 배경은 예외입니다.
- 글자가 잘리거나 로딩 중이거나 스켈레톤, 스피너가 남아 있으면 안 됩니다. 애니메이션과 데이터 로딩이 끝난 뒤 찍습니다.
- 찍은 뒤 이미지를 Read로 직접 열어 확인합니다. 잘림, 빈 화면, 오류, 어색한 데이터가 보이면 다시 찍습니다.
- 실제 이메일, 실제 사람 이름, 실제 GitHub 계정, 토큰이 보이면 찍지 말고 보고합니다. `allowLeak`은 쓰지 않습니다.
- 개발 배지나 토스트가 있으면 `shot`이 막습니다. 성공 토스트가 꼭 필요하면 `allowLeak` 대신 성공 문구를 매니페스트에 텍스트로 적습니다.

## 블러와 빨간 박스 (필수)

`shot(p, role, name, { blur: [target...], marks: [target | { target, label }] })`. target은 CSS 선택자나 Locator입니다.

- **블러:** 사람을 가리키는 값은 모두 가립니다. 사람 이름, GitHub 아이디, 아바타(이니셜 포함), 학번, 교직원 번호, 전화번호, 이메일이 대상입니다. 제목, 필드 라벨, 프로그램 이름, 팀 이름, 상태 배지, 날짜, 건수는 가리지 않습니다. 대화상자 문장 속 이름은 해당 텍스트 범위를 span으로 감싸 가립니다.
- 조직 이름 `JNU-SWCU`는 본문에서는 그대로 쓰지만, 화면에 보이는 곳은 가립니다.
- 오른쪽 위 헤더의 계정 영역(아바타와 아이디)은 항상 가립니다. 이니셜 아바타도 개인정보이므로 계정 영역 전체를 가립니다. 전체 화면 샷에서 가장 많이 빠뜨립니다.
- **빨간 박스:** 독자가 눌러야 할 것이나 봐야 할 것에 칩니다. 한 장에 1~3개이며 전부 치지 않습니다. 순서가 있으면 `label`로 `1`, `2`를 붙이고 본문 단계와 맞춥니다.
- **박스 대상:** 표 칸(td)이 아니라 컨트롤 자체(select, button, a)를 잡습니다. 칸을 잡으면 박스가 내용보다 커져 무엇을 가리키는지 흐려집니다. 박스 대상의 크기가 20px 미만이면 `shot`이 오류를 내므로(`mark target is WxHpx, under 20px`) 더 큰 요소를 고르세요.
- **박스는 실제로 눌리는 요소에 칩니다.** 버튼처럼 보여도 일반 글자일 수 있습니다. 눌러서 확인하기 전에는 "누르세요"용 박스를 치지 않습니다. 눌리지 않으면 제품 결함 후보로 적습니다.
- **번호 배지와 박스 선은 글자를 가리지 않습니다.** 배지는 박스 오른쪽 위에 놓입니다. 체크박스처럼 작은 대상은 배지가 옆 글자를 덮으니 그 줄 전체나 오류 문구를 잡습니다. 박스가 날짜나 제목을 가로지르면 대상을 글자 전체로 넓히거나 다른 요소로 바꿉니다. 찍은 뒤 배지 밑 글자를 읽을 수 있는지 열어 봅니다.
- **블러는 한 장 안에서 일관되게 합니다.** 같은 값이 한쪽은 가려지고 한쪽은 보이면 안 됩니다. 파일 이름은 사람을 가리키지 않는 한 가리지 않습니다.
- **브라우저 기본 컨트롤의 언어를 확인합니다.** 파일 입력칸 같은 기본 컨트롤은 페이지가 아니라 브라우저 언어를 따릅니다. `Choose File`처럼 영어로 찍혔으면 한국어 브라우저로 다시 찍습니다. macOS에서는 `locale`과 `--lang`이 먹지 않으므로, Chrome을 `-AppleLanguages (ko) --remote-debugging-port=<포트>`로 직접 띄우고 Playwright `connectOverCDP`로 붙습니다.
- 랜딩용 이미지(`landing/`)는 블러만 하고 박스는 치지 않습니다.
- alt와 caption에는 사람 이름과 아이디를 쓰지 않습니다.
- 매니페스트에 `marks` 열을 두고 박스 번호와 그 대상의 실제 라벨을 적습니다.

## 쓰기 동작 규칙

- 대화상자를 여는 것은 자유입니다. **확정 버튼은 원칙적으로 누르지 않습니다.** 캡처 에이전트끼리 DB를 공유합니다.
- 결과 화면이 꼭 필요하면 자기 역할 전용 페르소나로만 확정하고 무엇을 바꿨는지 매니페스트에 적습니다. 다른 역할이 쓰는 페르소나의 상태는 바꾸지 않습니다.
- 데이터가 더 필요하면 기반 준비 SQL을 고치지 말고 `scripts/psql.sh`로 새 합성 행을 추가합니다. 이메일은 `*.invalid`, 이름은 합성 이름만 씁니다.
- `github.com` 같은 외부 링크로 이동하지 않습니다. 실제 메일이나 GitHub 호출을 만들지 않습니다. `apps/`와 `scripts/`는 수정하지 않습니다. `.env`류는 읽지 않습니다.

## 화면으로 사실 확인 (캡처만큼 중요합니다)

사실표는 코드만 보고 썼습니다. 찍으면서 대조합니다.

- 사실표의 라벨과 실제 화면이 다르면 화면이 맞습니다. 차이를 보고합니다.
- 사실표의 `확인 필요`, `[추론]`, `추정` 중 자기 화면으로 판별되는 것은 판별해서 보고합니다.
- 제품 결함으로 보이면 Area / Observed / Expected / Evidence를 적습니다. 고치지 않습니다.

## 산출물: `<G>/manifest-<role>.md`

장마다 표 한 줄: `src`(`<role>/<name>.webp`), 페르소나, 경로, 보이는 것, `marks`, alt(한국어 한 문장, 화면 내용을 구체적으로), caption(한국어 짧은 설명), 어느 작업에 쓰는지. 이어서 다음을 적습니다.

1. 사실표 대조 결과(다른 라벨, 판별한 확인 필요 항목, 화면에서 확인한 성공 신호)
2. 못 찍은 화면과 이유
3. 제품 결함 후보
4. 바꾼 데이터

최종 보고는 짧게: 장수, 매니페스트 경로, 못 찍은 것, 눈에 띄는 불일치만 씁니다. 글쓴이는 매니페스트를 읽습니다.
