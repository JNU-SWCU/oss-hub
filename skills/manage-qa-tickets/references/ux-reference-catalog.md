# UX 레퍼런스 카탈로그

OSS Hub QA 티켓의 `참고 UI`에 반복해서 등장하는 제품 레퍼런스의 원본이다.
개별 티켓은 여기의 URL과 경계를 다시 서술하지 않고 이 문서를 가리킨다.
후보 탐색 범위, aspect-scoped 승인, 거절된 후보 처리 규칙의 원본은 [SKILL.md](../SKILL.md)의 UX 개선 절이다.

## 1차 레퍼런스 — daker.ai

| 항목 | 값 |
| --- | --- |
| 제품 루트 | `https://daker.ai/` |
| 착안 출처 | `https://daker.ai/public/hackathons` |
| 대표 상세 화면 | `https://daker.ai/public/hackathons/<대회-slug>` |
| 관계 | OSS Hub의 공개 프로그램 목록과 프로그램 상세는 이 화면 구조에서 착안했다 |

### 빌려오는 것

공개 상세 화면의 정보 밀도 조절 방식이다.
장문 설명 블록을 접이식 섹션으로 접어 두고, 참여자가 실제로 실행해야 하는 대상을 화면 위쪽에 남긴다.
접힌 상태에서도 제목과 아이콘만으로 그 안에 무엇이 있는지 판단할 수 있게 한다.
섹션마다 앵커를 두어 목차에서 바로 이동할 수 있게 한다.

### 가져오지 않는 것

브랜딩, 카피 문구, 색과 타이포그래피는 가져오지 않는다.
OSS Hub의 디자인 토큰과 component 계약이 계속 원본이다.
랭킹, 리더보드, 상금 표시처럼 OSS Hub에 대응 개념이 없는 기능은 참고 대상이 아니다.
daker.ai의 라우팅 구조나 URL 형태를 모방하지 않는다.

### 캡처 취급

제3자 제품 화면 캡처는 Notion 티켓에만 올린다.
공개 저장소, GitHub Issue, PR 본문에는 URL만 남기고 이미지를 반입하지 않는다.
캡처는 `/public/` 경로처럼 로그인 없이 접근 가능한 화면에서만 뜬다.
캡처에 실제 사용자 이름, 이메일, 팀명이 보이면 폐기하고 다시 확보한다.

## 레퍼런스를 추가할 때

새 제품을 이 카탈로그에 올리는 조건은 두 개 이상의 티켓에서 다시 인용될 것으로 보일 때다.
한 번만 쓰는 레퍼런스는 카탈로그가 아니라 해당 티켓의 `참고 UI`에만 둔다.
추가할 때는 위 표와 같은 형식으로 제품 루트, 착안 출처, 빌려오는 것, 가져오지 않는 것, 캡처 취급을 모두 채운다.
빌려오는 것과 가져오지 않는 것 중 한쪽이 비면 그 레퍼런스는 경계가 없는 것이므로 올리지 않는다.
